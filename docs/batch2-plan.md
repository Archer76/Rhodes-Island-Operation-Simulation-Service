战斗层没人消费，**不算数**——闪避此前就是这样整条链路静默失效的（见 `roadmap.md`）。

## 一句话结论

**先做召唤物。** 理由不是它最简单，恰恰相反——它牵扯最广，而且是练度第一的
**电弧**的整套 kit：电弧技1/2/3 各换一种塔，塔本身就是召唤物。她现在的战斗行为
等于零。数据层已经查清、够用（见下节），所以这是**最该先做也做得动**的一件。

## 六个大件 × 干员

### 已实测确认：召唤物

判据是**数据**不是关键词——`operator_skill.override_token_key` 与
`operator_talent.token_key` 指向哪个 token，这是权威。

| 干员 | 召唤物 | 性质 |
|---|---|---|
| 电弧 | `token_10051/52/53_radian_tower1/2/3`（戴乌 / 赛柯 / 桑特拉） | **真单位**：技1/2/3 各一种塔 |
| 令 | `token_10020_ling_soul1/2/3`（"清平" / "逍遥" / "弦惊"） | **真单位**：技1/2/3 各一条龙 |
| 望 | `token_10064_wang_stone1`（棋子） | **真单位**：天赋「铸子」+ 技1/2/3 |
| 机械师 | `token_10069_mcnist_mcgraf`（结构性原理） | **标记**，不是单位（见下） |
| 圣聆初雪 | `token_10058_sbell2_icetgt`（保护目标·冻结状态） | **标记**：技2 的作用目标点 |
| 予愿安洁莉娜 | `token_10071_aglna2_agairp`（"一会儿见！"） | **标记**：技3 的空投坐标 |

⚠️ **标记与真单位必须分开**，这是这一件里最容易做错的一步：三类标记的
`operator_attr` **全为 0**（hp/atk/def 都是 0.0），而且 `operator_phase.phase` 只有
`-1` 一行。若按 `token_key` 无脑建单位，会造出三个 0 血 0 攻、站不住也打不动的
幽灵单位。判据：**phase 含 `0/1/2` 且 hp > 0 才是真单位**。

从召唤物反查需要的支撑（也都是真单位，属同一件工作）：
`token_10057_svash2_eagle1/2/3`（风雪之眼）等 73 个 token 都在库里。

## 召唤物的数据层：已查清

| 问题 | 答案 |
|---|---|
| 召唤物在库里吗 | **在**。`operator` 表里 `is_operator=0` 共 703 条，其中 73 条是 `token_*`；职业列为 `TOKEN`，子职业「干员附带单位」 |
| 有没有属性 | **有**。`operator_attr` 每 token 6–8 行（含 E0/E1/E2 各档），hp/atk/def/res/cost/block_cnt/攻速/再部署/部署上限/库存齐全 |
| 有没有技能 | **有**。多数 0–3 个技能槽，且技能内容与本体同样走 `skill` / `skill_level` |
| 有没有天赋 | **有**。`operator_talent` 有行，部分带自己的黑板 |
| 能不能当单位建出来 | **能**。`battle.unit.OperatorUnit` 的字段（`char_id` / `position` / `direction` / `block_cnt` / `deploy_cost` / 属性 / `skill`）足以承载 |

实测出来的两个数据问题（**不是**我这边的代码问题，先记录）：

1. **悬空引用**：`token_10057_svash2_eagle` 被 `token_key` 引用，但 `operator` 表里
   **没有**这一条；真实存在的是 `token_10057_svash2_eagle1/2/3`（风雪之眼）。
   取召唤物时对不上号要**如实报出来**，不能静默跳过。
2. **标记冒充单位**：见上节三类。
