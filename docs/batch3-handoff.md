## 二、审计判据（务必先理解这一节，否则会误判"做完了"）

`tools/audit_coverage.py` 有**三道筛子**，**只有前两道是任务书里写的判据**，第三道是本会话新加的：

1. **`_classify(key) is None`** —— 这个键落进 `other` 桶了吗？
2. **「无人读」** —— 键的字面量在 `ak_tactic/` 源码里出现过吗？
   **只在第一道失败（即归不了类）的键上运行**；方括号变体键按**条件名**判定。
3. **天赋级筛** —— 天赋**名字**在源码文本里出现过吗？
   若某天赋的**全部**键都在 `GENERIC_TALENT_KEYS`（当前 = `{"attack_speed"}`）里，则豁免。

### ⚠️ 两个会导致"假零欠账"的盲区（本会话撞了三次）

* **盲区一**：`atk` / `def` / `max_hp` / `attack_speed` / `prob` / `atk_ratio` 这些键**归得了类**，
  所以**永远不会走到第二道筛子**。于是**一条完全没有检测器的天赋会被报成零欠账**。
  实例：星熊「战术装甲」、阿斯卡纶「死亡拘审」与「噬光残影」，三次同型。
* **盲区二**：第三道筛按**天赋名字**判，所以**无名天赋是隐形的**。
  322 行 / 213 位干员有无名黑板（焰狐龙梓兰组 2 的 `attack@damage_scale=0.333`、
  组 3 的 `respawn_time=-15` 即属此类）。它们的键仍会进 `allk`，由前两道筛子覆盖。

### ⚠️ 一条比筛子更重要的纪律

**审计归零 ≠ 机制完整。**

筛子量的是「**有没有人读**」，不是「**读全了没有**」。样板实例：**能天使**三道筛子全部清零，
但「天使的祝福」的**「同样赋予一名随机友方」那半没有做**（见第五节）。
本会话已在 `talents.py` 的 docstring、`docs/uncertainties.md` 第十五节、以及在
`tools/check_battle.py` 守卫 `[33]` 的标题里**三处标注**这件事。

## 八、施工坑（**下一个会话务必先读这一节**）

### 8.1 行尾是 CRLF —— 本会话为此连栽三次

`ak_tactic/battle/sim.py`、`tools/check_battle.py` 等工作区副本是 **CRLF**
（`git add` 时会警告 "LF will be replaced by CRLF"）。后果三连：

* 用 PowerShell 按 `` "`n" ``（LF）拼的锚点，`Contains` **永远为假**；
* `[regex]` 的 `(?m)$` 被行尾的 `\r` 挡掉，**不匹配**；
* **多行替换静默不生效**——脚本照跑、退出码 0、**什么都不改**。

**纪律**：改这些文件**优先用 `edit` 工具**（它自行归一行尾）。
非要用脚本，就按 `-join "`r`n"` 拼，或**只用不含换行的单行子串**做锚点。

> `edit` 报 `cannot edit ... file changed since it was read` 时，
> 用 **`read` 工具**读一下那个区间即可；
> **用 `Select-String` / `grep` 读不算「已读」**。

### 8.2 PowerShell 转义

* 双引号字符串里**再套 ASCII 双引号**会解析失败 → 用「」。
* **反引号是转义符**：`` `e `` 会被当成 ESC 字符写进文件。
  写含反引号的文本（如 Markdown 行内代码）请用**单引号 here-string `@'...'@`**。
* `.NET` 静态调用按**进程 cwd** 解析，不是 `cd` 的结果 → 传绝对路径。

### 8.3 全局子串替换会**静默削弱断言**

本会话把 `potential=3)` 全局换成 `potential=6)`，而 `check_battle.py` 里有**两处**
（星熊「战术装甲」在潜能 3 到 28%、能天使「天使的祝福」在潜能 6 才到 8%/13%），
星熊那条被一起改了——**因为它潜 3 与潜 6 都是 28%，测试仍然全绿**。

**纪律**：替换前先数出现次数（`[regex]::Matches(...).Count`），并用足够长的上下文做锚点。

### 8.4 数据侧的坑

| 坑 | 说明 |
|---|---|
| **天赋候选按精英/等级取档** | `operator_talent` 同一个 `(char_id, name)` 有多行，按 `unlock_phase` 分档。**一律走 `TalentBook().for_operator(char_id, elite=, level=, potential=)`**，**绝不** `SELECT ... WHERE required_potential_rank=0` |
| **`operator_trait` 同理** | 按 `char_id` + `unlock_phase` 存，同样不能只取一行 |
| **`required_potential_rank` = 潜能号 − 1** | rank 5 → 潜能 6 |
| **技能等级** | 1–7 与专精分开：`sk.level(level=7, mastery=3)`；SQL 里 `level` 8–10 = M1–M3 |
| **键名驼峰 vs 蛇形** | 库表列是**蛇形**（`nation_id`），但 `OperatorCalculator.character()` 返回的字典是**驼峰**（`nationId` / `teamId` / `subProfessionId`）。**照库名写 `get("nation_id")` 会静默取到空** |
| **归属三列是三件事** | `teamId` = **小队**（`student`/`rainbow`/`reserve6`…）、`nationId` = **国家/势力**（`rhodes`/`lungmen`）、`groupId` = **组织**（`lgd`/`penguin`）。**反例**：能天使 `teamId` 是 `None` 却属**龙门**，阿米娅同样是 `None` 却属**罗德岛**——判「是不是【罗德岛】」只能 `nationId == 'rhodes'` |
| **两库不可混** | 干员库 `data/akdb.sqlite`、敌人库 `data/enemydb.sqlite`，**不共用文件**，数值约定相反 |
| **`Tile.is_highland` 是属性** | 不是方法，写 `()` 会 `TypeError: 'bool' object is not callable` |
| **`OperatorUnit.attack_speed` 是总值** | 含基础 100（阿斯卡纶带天赋时是 108，不是 8） |

### 8.5 测试自身的坑

* **端到端断言才是唯一有信息量的**。本会话两次靠它救命：
  泥岩的 `category` 与可露希尔的 `nation_id`——**纯逻辑断言全绿，红的只有端到端那一条**。
  给机制补数据源时，**必须跑一局真实对局验它真的触发了**。
* **每加一个机制都要配一条反向守卫**（"别人不白拿"）。
  只有正向会漏掉"永远为真"这类错。
* 本项目的失败反复**"看起来像成功"**：bound-method-in-set、`getattr` 返回 `{}`、
  正则列位移、latch 式阻挡、解析了但没接线、加了机制没加字段。
  **取数禁用 `getattr(obj, x, None) or {}`**。
