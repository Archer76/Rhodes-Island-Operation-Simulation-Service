# 地图机制：获取与格式化

每个活动／章节都会引入一批新的地图机制。这些机制**不像干员或敌人那样有稳定的
数据表**，它们散落在两个地方：全局术语表与单关页面。本层负责把它们取回来、
整理成可编译的文本，并复用既有的规则扫描产出公式项。

与另外两层的分工：

| 层 | 语料 | 模块 | 命令 |
|---|---|---|---|
| 干员 | gamedata 的技能／天赋／特性正文 | `ak_tactic/formula.py` | `python -m ak_tactic formula` |
| 敌人 | prts.wiki 的敌人技能与天赋 | `ak_tactic/enemy_formula.py` | `python -m ak_tactic enemydb formula` |
| **地图机制** | **prts.wiki 特殊机制表 + 关卡页字段** | **`ak_tactic/mechanics.py`** | **`python -m ak_tactic mechanics`** |

## 三条事实来源

**必须能分辨某个数值出自哪一条**，所以输出里分别标明。

1. **全局术语表** —— prts.wiki「特殊机制」页。当前实测 **87 条**，分九节：
   单位类型、阵营、职业、额外术语、战场效果、引擎机制、伤害机制、复用机制、
   特殊计算方式。条目形如 `特殊机制表格|名称|说明|备注|图标`。
2. **单关实数** —— 关卡页的「特殊地形效果」「关卡描述」「情报」字段。
   这是**公式里那些数字真正的出处**。
3. **gamedata 侧** —— 关卡 JSON 的 `runes[].blackboard`、`predefines.tokenInsts`、
   `environmentSe`。注意黑板条目形如 `key/value/valueStr`：**数值型键的值住
   `value`，`valueStr` 恒为 `null`**；只有 `init_pollut_value` 这类字符串住
   `valueStr`。只读 `valueStr` 会得出「参数全是 None」的假结论。

两条来源互为校验。怀黍离已实证：关卡页 HS-8 写的「每秒受到 20+病害值×3
法术环境伤害」与关卡 JSON 的 `basic_damage=20` / `damage_ratio=3` 逐项吻合。

## 命令

```
# 列全表（可按名字子串过滤）
python -m ak_tactic mechanics
python -m ak_tactic mechanics 病害值

# 看某一关的机制字段并编译
python -m ak_tactic mechanics --stage "HS-8 种因"

# 覆盖率与未命中的高频残句
python -m ak_tactic mechanics --scan --top 30

# 机器可读
python -m ak_tactic mechanics 田地 --json
```

自检：`python tools/check_mechanics.py`。绝大多数检查是**离线**的——正文用的是
逐字抄自 prts.wiki 的字面量，只有「活页面」与覆盖率两节要联网，取不到就跳过。

## 解析的三个坑

1. **切参数要按嵌套深度。** 说明栏里嵌着同层模板（`异常效果`、`术语`、`color`），
   裸 `split("|")` 会把内层的 `|` 当成分隔符，说明栏被切碎、备注与图标整体错位。
   见 `split_args`。
2. **找模板结尾要按花括号配平。** 非贪婪正则 `特殊机制表格\|(.*?)\}\}` 会在**嵌套
   模板的** `}}` 处提前截断，把后半句丢掉——而截出来的前半句看着完全正常，
   不报错。见 `_iter_templates`。
3. **小节层级。** 真页面把 `===` 当作顶层节（`==` 是页面标题级），`====` 才是子节。
   按 `层数 - 2` 算嵌套深度，遇到 `==` 会得出负深度并当场 pop 空列表；
   用 `max(0, 层数 - 3)`。见 `_section_at`。
4. **引用里的机制名不一定是第一个参数。** 页面上存在**命名参数在前**的写法：

   ```
   {{特殊机制|名称=病害|病害值|color=yellowgreen}}     ← 怀黍离活动页原文
   ```

   机制名是第 0 个**位置**参数「病害值」；`名称=病害` 只是显示标签。
   只取第一个参数会读出 `名称=病害`——机制名整个错掉、与术语表也不匹配。
   见 `ref_name`（取第一个不含 `=` 的参数）。

### ⚠ 引用名 ≠ 条目名（三类，扫描全量缓存页得到）

「这一页引用了哪个机制」记的是**页面上的写法**，它与术语表的**条目名**并不总
一一对应。将来要做"引用 → 条目"的解析器时，下面三类得先处理：

| 类别 | 页面上的写法 | 术语表里的名字 |
|---|---|---|
| 合并条目 | `明` / `晦`（`登场时获得【明】属性…`） | **明晦属性**（一条） |
| 带标点 | `附着：` | `附着` |
| 子名 | `弱点（P3R）` / `免疫（P3R）`（「死志的凝结」正文） | `伤害相性（P3R）`（前两者是它的两种取值，本身不是条目） |

现在**不做**归一化：这些名字目前只用于 CLI 展示，没有消费者按它查表；真做归一化
得连带决定"一个引用能不能对上多条"，不该顺手定。

`{{特殊机制|…}}` 还是**唯一**会把整段引用洗成空串的形态（正文取位置参数 0，
全为命名参数时 `detemplate` 返回空串）。`check_enemy_formula.py` 里有一条守卫
盯着"语料里没有展开成空串的调用"——当前 1023 处调用、0 处为空。

## 规则表与顺序

`MECHANIC_RULES` **排在干员与敌人规则之前**——这与敌人侧相反，理由是锚点的独特性：
「环境伤害」只出现在地图机制里，排在后面会被通用伤害规则先咬走；而敌人侧的新规则
更粗，必须排在干员规则之后。顺序即优先级，命中即消费区间。

机制规则只锚**尾巴**，数值形状交给算式通道：怀黍离的原文是
「基础值 + 系数×变量」的**加法**，把 `20+病害值×3` 当常数取会得到看着对、
其实错的表达式。产出 `Term.amount is None`、结构保留、数值留白。

### ⚠ 词序：同一个机制，两个来源的写法不一样

| 来源 | 原话 |
|---|---|
| 关卡页（HS-8 / HS-EX-8） | 法术**环境伤害** |
| 术语表「病害值」条目 | **环境**法术伤害 |

**两条规则都要有**（`mech_env_damage` / `mech_env_damage_alt`）。只写一条会得到
一条永不命中的**死规则**——而它看着毫无问题。自检里因此有一条「机制规则没有一条
是死的」守卫，语料必须**同时喂术语表与关卡页锚点**：只喂术语表会把关卡页那条误判
成死规则，只喂锚点则反之。

### ⚠ 规则一律锚正文原话，绝不锚条目名

条目名常常不在正文里出现。「停顿免疫」的正文写的是「使停顿无法生效」，
压根没有「免疫」二字——按名字写规则会得到又一条永不命中的死规则。

### 无数值的效果怎么落

「无视闪避」「免死」「不可重伤」「无害目标」这类**没有数值**的机制，
用 `form: "word"` + `flag=` 落成 `Term`（`amount` 留白、`expr` 是标记词）。
不塞进一个笼统的 `flag` 是不够的，故按语义分了 `mech_ignore` / `mech_immune`：
「查出所有无视闪避的机制」不该是全文搜索。

### 定义 ≠ 效果：两份名单

- `NON_EFFECT_NAMES` —— **本就不该编译**的条目（「阵营为我方的单位」「曼哈顿距离
  相当于…」）。这几节覆盖率低是**对的**，与敌人侧 `desc` 只该到 55% 是同一回事。
  自检断言它们**仍然**编不出东西。
- `KNOWN_MISPARSE` —— **编错了**的条目。它们确实是定义，却被**同一条敌人规则**
  越界咬走：`e_place` 把「初始**放置**在场上」读成地形改造，`e_summon` 把
  「战斗开始即**生成**的场合」读成召唤。

  **两类错误的区别很要紧：编不出来是漏，编错了是错，错比漏糟。** 把后者硬塞进
  `NON_EFFECT_NAMES` 会让守卫自己骗自己（那条断言的是"编不出东西"），所以单独记账。
  自检盯着它们**仍在被误读**；哪天规则收紧了那条会红，红了就移进 `NON_EFFECT_NAMES`。

⚠ 名单**必须逐条读过正文再写，不能按名字猜**。第一版凭名字往里放了「角色类单位」
与「可空降」，两条其实都有可结算的效果——按名字猜会把真效果划成"不该编译"，
而自检只会照着这份名单断言，**错误就被自己的守卫背了书**。

## 当前水位

写这段时的实测值，**会漂，别抄**：

```
python -m ak_tactic mechanics --scan
```

写这段时：术语表 87 条，编译出公式项 49 条 = **56.3%**。分节上「伤害机制」8/10、
「战场效果」6/7，而「阵营」「职业」「特殊计算方式」为 0——那几节是**定义性散文**，
本就不该编译出公式项。

覆盖率下限（**判据，不是水位**，低于即说明规则表被改坏）：总 ≥ 50%、
「战场效果」≥ 70%、「伤害机制」≥ 70%；另有三条**上限**守卫（「阵营」「职业」
「特殊计算方式」≤ 34%），哪天被"顺手"补上就说明有人把定义当效果收了。
