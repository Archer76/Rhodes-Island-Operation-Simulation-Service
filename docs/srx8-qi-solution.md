|---|---|

方案稳健的证据**，那正是旧默认值干的事。

## 二、两条硬规则（博士实机确认，本文档全部结论都架在上面）

### 规则一：相性「免疫」= 该类型伤害**全部归零**

不是"只挡击破值"。我一度据「BOSS 在标着法术免疫的 Mode_A 里法抗只有 20」
推断免疫只影响击破值累积，**推错了**。免疫与法抗并存不是冗余：免疫决定
"完全打不动"，法抗只在**非免疫**的那一侧生效。

代码落点：`p3r.affinity_multiplier(..., immune_blocks_damage=True)` 返回 `0.0`；
`BattleSimulator(affinity_blocks_damage=True)` 是默认值；`run_plan` 的默认值
**必须与它一致**——曾经只改了前者、忘了后者，结果"免疫"那一侧被静默放行，
跑出一个漂亮的假胜利矩阵。

### 规则二：BOSS 每**倒地一次**就翻转一次免疫类型

`Mode_A`（物弱·法免）↔ `Mode_B`（物免·法弱），一倒地一翻。
**不是**每倒地两次：我曾从同类敌人 `几点了钟` 的 `PowerAttackTrigger.trigger_cnt = 2`
反推 `Mode_A.trigger_cnt = 2` 是"条件满足 2 次触发"，**推错了**——这个字段在两个
prefab 上不是同一回事。

代码落点：`sim._note_knockdown` 无条件调 `_switch_boss_mode`，不读 `trigger_cnt`。

### 由两条规则推出的死结，与解开它的钥匙

`Mode_B` 里物理伤害归零 **且** 击破值只按**实际掉血量**累积（`BreakState.add`
要求 `affinity == P3R_WEAK`）——所以物理连击破值都攒不出来，**必须靠法术把它打倒
才能翻回 `Mode_A`**。反过来在 `Mode_A` 里只有物理能动它。任何**单一伤害类型**的
队伍都会在它的另一半形态里彻底哑火。这也解释了为什么旧编队（纯物理+纯法术的
混合但各自固定）在 knock 读法下全军覆没：

| 旧编队 | knock 读法下的实测 |
|---|---|
| 五人·主方案（机械师+安洁+阿斯卡纶+凯尔希+圣聆） | 31 杀 3 漏，失败 |
| 四人·压人数 | 22 杀 4 漏，失败 |

**钥匙是赤刃明霄陈的天赋「形意洞照」**：她的攻击变为**弱点伤害**——每次结算都按
物理与法术各算一遍取高者。免疫归零之后，"高的那一种"自然就是**当前没被免疫的
那一种**，于是她在两套形态里都打得动、都攒得动击破值。技3 再补上剑气与
范围扩大的平A。

## 三、她这一套具体怎么算的

### 剑气（技3）——按博士给的四条口径建模

原文：「技能开启时**向前**释放一道**可转向**的剑气，对穿过的敌人造成相当于其
当前生命值 6% 的法术伤害（至少造成自身攻击力 580% 的法术伤害）」。

| 口径 | 来源 | 落点 |
|---|---|---|
| 向前走，遇障碍物**右转** | 博士 | 屏幕右转 = 项目坐标 `(dx,dy)→(dy,−dx)` |
| 直到技能结束时消失 | 原文 | 主人 `skill_active` 为假即移除 |
| 直行时同一敌人只吃一次，**拐弯后刷新状态** | 博士 | 转向时 `q["hit"].clear()` |
| 伤害 = max(当前生命 6%, 攻击力 580%) | 原文 | `max(e.hp*0.06, atk*5.8)` |

**速度是未知量**：原文没写，模拟器给 4 格/秒。已扫描 v=1…20（九档，见第一节），
**每一档都取胜**，只有 v=1 与 v=2 会漏 2 只（仍在 3 命之内）——这条未知量
**不再威胁结论**。这是补上下面那条三连击之后的改善：补之前 v≤2 会直接崩。

### 范围扩大的平A：3 连击 × 210%，最多 4 名地面敌人

这一条**黑板里没有**。技3 的黑板只有：

```
hp_ratio 0.06   projectile_min_atk_scale 5.8   attack@atk_scale 2.1   attack@max_target 4
```

而那个「3 次」**硬写在描述正文里**：

> 每次攻击对最多 4 名地面敌人造成**3 次**攻击力 210% 的法术伤害

只读黑板会把这一击按 `210% × 1` 算，**少算三分之二**。所以新增
`_repeat_hits(description)`：剥掉 `<@ba.vup>3</>` 这层富文本标签后取
`造成N次攻击力`。判据收得很紧——**全表 1.1 万个技能里只有这一例命中**，
不会波及其它干员。

补上三连击之后，BOSS 倒地次数从 15 降到 10（伤害更集中，不需要靠倒地次数堆总伤害）。

> 当时我据此写下「剑气速度的敏感度整段消失」——**那是稀疏扫描造成的错觉**：
> 只跑了 1 / 1.5 / 2 / 3 / 4 … 这些点，恰好跳过了 **1.2–1.25** 这个会漏 1 只的
> 窄区间。2026-09-16 在实测值附近细扫 11 档后，敏感度是**真实存在**的：
> 1.2 漏 1、1.3 漏 2、1.5 不漏。教训是扫描点要按**未知量的可能取值**布，
> 不能按"看起来整齐"布。

## 五、必须随作业说出去的偏差

- **阵亡**：模拟里赤刃明霄陈在 172s 阵亡（她站在 BOSS 走廊上硬吃伤害），
  但**此时局面已定**：收场 39 杀 0 漏 3 命。MAA 不因干员阵亡判失败。
- **未建模**：元素损伤、咆哮铳炸膛与吓人路灯屏障引起的弱点失效、召唤物、
  嘲讽等级、凯尔希天赋2 的护盾层与【罗德岛】翻倍（两处都偏保守）、
  结城理天赋2 的 450% 真实伤害。
- **剑气的伤害类型**按"弱点伤害"走自适应（用户口径：她任何时候都能打弱点伤害），
  而不是原文写的固定法术。
- **`requirements.module` 的语义**（博士实机纠正，两条）：写的是**模组类型编号**
  ——游戏里模分 X / Y / Z 三型，MAA 写 **1 / 2 / 3**。**不是**模组 id 里的序号：
  赤刃明霄陈的 `uniequip_002_chen3` 是 **X** 型要写 `1`，圣聆初雪的
  `uniequip_002_sbell2` 是 **Y** 型要写 `2`——两条的 id 序号都是 002。我先前按
  id 里的数字填，把她写成 2，错了。数据出处是
  `uniequip_table.equipDict[<id>].typeName2` 那个字母。
  另一条：**没有生效模组的干员必须整个省略这个键**，写 `0` 会让 MAA
  **不识别整份作业**（不是忽略该要求，是整份用不了）。现已由
  `export_srx8.module_slot()` 保证，并在每次导出时打印判定过程。
- `module_level` 在协议里有字段，但 `requirements` 整块官方标注「保留接口，暂未
  实现」，模组等级仍须人工确认到 Lv3（本作业：赤刃明霄陈 X 模组、圣聆初雪
  Y 模组）。
