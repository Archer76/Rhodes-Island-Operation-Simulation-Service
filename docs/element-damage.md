# 元素损伤（元素值 / 爆条 / 爆发冷却）

> 判据出处：PRTS [`元素`](https://prts.wiki/w/元素) 页（`元素损伤` 重定向至此，
> 页面最后编辑 2026-09-19）＋ [`游戏数据基础`](https://prts.wiki/w/游戏数据基础) §5.2.3「元素伤害」。
> 落点：`rios-sim/element.go`（机制内核）＋ `rios-sim/element_test.go`（7 条守卫）。

## 一、元素值（EP）

**每种元素单独记一份元素值，初始为最大值**（像血条，不是从 0 往上累计的计数器）。

| 量 | 默认 | 说明 |
|---|---|---|
| `MAX_EP` | **1000** | 领袖级**敌人类**单位变为 **2000**（"与其属性上限"） |
| `EP_RECOVERY_PER_SEC` | 0 | 每秒回复量 |
| `EP_RESISTANCE`（损伤抵抗） | 0 | 单位 % |

```
受到的（元素）损伤 = 损伤值 × (1 − 损伤抵抗 × 0.01)
```

之后还可再叠「元素损伤倍率提升/降低」。**中立阵营的实体无法受到元素损伤。**

> ⚠ 与「元素**伤害**」是两回事：损伤吃的是**损伤抵抗**，伤害吃的是**元素抗性**。
> `游戏数据基础` 原文就写了「目标受到元素损伤时也可以使用该公式计算，只需要将
> `D` 值改为目标的损伤抵抗即可」——两处别串。

## 二、爆条与爆发冷却（三条最容易写错的规则）

1. **某一项元素值降低至 0 时触发爆发**（俗称"爆条"）。
   等价于"累计到 1000"，但**按"降到 0"实现**：一旦出现上限差异或回复，
   两种写法立刻分道扬镳。
2. **爆发开始 → 进入爆发冷却**。冷却期间：**单位所有类型的元素值均无法损失、
   也无法被其他手段回复**——是**对所有元素**免疫，不是只对爆掉的那一种。
   （模型上那截"缓慢恢复至上限"只是动画。）
3. **爆发结束时，冷却一并结束，随后单位所有种类的元素值恢复至最大值。**
   ⇒ **不是"扣掉 1000、余量留着"**。按余量写，连续两次爆条的时刻会整体错位。

另外两条：
* **当前损伤元素** = 元素值**最低**的那个（平手按元素 ID 升序），只用于索敌与图标；
  「不代表实际发生元素损伤爆发的元素」——爆发取决于**首个施加**的那一种。
* 爆发伤害**无来源**，但归属"造成爆条的那个来源"。

## 三、两列爆发效果（阵营分列，不能混）

PRTS 表按「我方角色类单位」与「其他单位」分两列。且原文注明：
**自 2026-04-07 更新后，敌人类单位无论阵营，损伤爆发时均使用"敌方单位受到的爆发效果"。**

| 元素（ID/内部ID） | 持续 | **对敌人**（`burstOnEnemy`） | **对干员**（`burstOnOperator`） |
|---|---|---|---|
| 神经损伤 `SANITY` | 10s / 10s | 麻痹震颤 0.5s ＋ **麻痹免疫**（3 层麻痹）；随后 **6000 元素** | 等时长**晕眩**；随后 **1000 真实** |
| 侵蚀损伤 `WATER` | **8s** / 10s | 立刻 **−120 防御**（永久、可无限叠加、**不被重生清除**）；**5000 元素** | 立刻 **−100 防御**（永久可叠）；**800 物理** |
| 灼燃损伤 `FIRE` | 10s / 10s | 爆发期间 **法抗 −20**；**7000 元素** | 爆发期间 **法抗 −20**；**1200 法术**（吃这次减抗） |
| 凋亡损伤 `DARK` | 15s / 15s | 等时长 **50% 虚弱**（随剩余时间衰减）；每秒 **800 元素** | 等时长**阻回＋静默**；每秒 **−1 技力**、**100 法术** |
| 狂躁损伤 `ANGER` | 15s / 15s | **无效果** | 攻速 **+50**；每秒 **X 真实**（100 起，每次能力 +50，**上限 600**） |

> ⚠ **狂躁对敌人一格是空的，这是原文，不是漏抄。**

## 四、元素伤害的结算式

`游戏数据基础` §5.2.3：

```
DMG_e = max[ 0.05·A, 0.01·A · max(0, 100 − D) ]        D = 目标的元素抗性最终结果
```

* **与法术伤害同式**，区别只在读**元素抗性**而不是法抗；**没有穿透项**。
* 已实现为 `resolveElementDamage(a, elementRes)`。爆发伤害是"无来源"的，
  所以**它不接闪避参数**——不要为了对称补一个。
* 损伤那一侧用的是第一节那条更简单、**没有 5% 保底**的式子（`elementDamage`）。
  两式在损伤抵抗 ≤ 95 时逐位相同；哪天发现抵抗能过 95，回来统一。

## 五、现状与未接线（如实登记）

* `rios-sim/element.go` 是**机制内核**：状态机（EP / 冷却 / 归满 / 当前损伤元素）
  ＋ 两张 5 行表 ＋ 两个结算函数；`element_test.go` 7 条守卫全绿。
* **尚未接线，也没有调用点**——与【寒冷】同一处境：原版 Python 侧同样零实现。
  接线时要做的三件事：
  1. 在敌人的构造处 `newElementState(maxEP)`；`maxEP` 要**进规格**（领袖 2000），
     不能在建对象时现查（规格快照陷阱）；
  2. 把"攻击附带的元素损伤"接到 `damage()`，爆条时按目标阵营取 `burstOnEnemy` /
     `burstOnOperator` 结算；
  3. 逐帧 `tick(dt)` 并把返回的那些元素归满。
* 数据源已就绪：敌人库 `enemy_level.element_resistance` 就是元素抗性那一列；
  损伤抵抗要从敌人/干员的属性或 Buff 取（`EP_RESISTANCE`）。

## 六、与机制词典（tooltip）的关系

`敌人一览/数据` 页的 tooltip 词典把五种元素损伤都写成一段话，那一段**全部是
"我方角色类单位受到的效果"列**。对敌人用这组数会**每一档都错**：

| 元素 | 词典（＝我方列） | 敌人列（本节权威） |
|---|---|---|
| 神经 | 1000 真实 ＋ 晕眩 10s | **6000 元素** ＋ 麻痹/麻痹免疫 |
| 侵蚀 | −100 防御 ＋ 800 物理 | **−120 防御 ＋ 5000 元素** |
| 灼燃 | −20 法抗 ＋ 1200 法术 | **−20 法抗 ＋ 7000 元素** |
| 凋亡 | 阻回/静默 ＋ 每秒 100 法术 | **50% 虚弱 ＋ 每秒 800 元素** |
| 狂躁 | 攻速 +50 ＋ 每秒 100 真实 | **无效果** |

结论：**词典能给"有没有这条机制"，给不了"对敌人是多少"**——后者只有 `元素` 页有。
