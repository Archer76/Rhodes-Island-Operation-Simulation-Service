### 这张图的核心机制是传送

地图形状是**左右完全镜像**的双路设计，而中枢在正中间：

- **5 个传送入口**（`I`）：`(0, 6)`、`(12, 6)`、`(0, 2)`、`(12, 2)`、`(6, 1)`
- **1 个传送出口**（`O`）：`(6, 5)` —— 地图正中央

敌人从左右两侧边缘的入口走进来，撞上传送入口后被丢进中央的 `(6, 5)`，
再从那里向下穿过 `(6, 7)`，最后分左右抵达两个防守点 `(4, 7)` 与 `(8, 7)`。

**39 条路线里有 38 条最终都汇聚到 `(6, 5)`**——唯一的例外是飞行路线。
所以整张图的**真正前线只有一小段**：

```
(6, 5) → (6, 7) → (4, 7) / (8, 7)
```

左右两侧那十几条看似复杂的路线，本质上都只是「把敌人送进中央」而已。

`(6, 1)` 那个传送入口最特殊——它在**正上方**，只有巡逻路线会经过。

## 五、路线结构

39 条被使用的路线，去重后只有 **15 种走法**，其中 12 种是高重复的镜像对：

```
(2, 2) -> (0, 2) -> (6, 5) -> (6, 7) -> (4, 7)      左上路
(1, 3) -> (0, 2) -> (6, 5) -> (6, 7) -> (4, 7)      左上，并入同一个传送口
(3, 3) -> (0, 2) -> (6, 5) -> (6, 7) -> (4, 7)      左上，同上
(10, 2) -> (12, 2) -> (6, 5) -> (6, 7) -> (8, 7)    右上路
(11, 3) -> (12, 2) -> (6, 5) -> (6, 7) -> (8, 7)    右上
(9, 3) -> (12, 2) -> (6, 5) -> (6, 7) -> (8, 7)     右上
(2, 6) -> (0, 6) -> (6, 5) -> (6, 7) -> (4, 7)      左下路
(1, 5) -> (0, 6) -> (6, 5) -> (6, 7) -> (4, 7)      左下
(3, 5) -> (0, 6) -> (6, 5) -> (6, 7) -> (4, 7)      左下
(10, 6) -> (12, 6) -> (6, 5) -> (6, 7) -> (8, 7)    右下路
(11, 5) -> (12, 6) -> (6, 5) -> (6, 7) -> (8, 7)    右下
(9, 5) -> (12, 6) -> (6, 5) -> (6, 7) -> (8, 7)     右下
```

四条主线（上路左/右、下路左/右）各自再分三个入口点，所以是 12 种基础走法，
每条被三个波次各复用一次。**12 条全部经 `(6, 5)` 汇聚**。

另外三条是特别的：

- **route 0**（没办法车）：
  `(6, 2) → (1, 2) → (1, 6) → (1, 2) → (11, 2) → (11, 6) → (11, 2) → (6, 2) → (6, 1) → (6, 5) → (6, 7) → (4, 7)`
  —— 在左右两个内圈之间**来回巡逻**，最后经正上方的 `(6, 1)` 传送口进入中央。
- **route 7**（BOSS）：同一条巡逻路径走**两轮**才进入中央，全长是本图之最。
- **route 38**（挥铳圣像）：`FLY` 模式 —— 唯一的**飞行**路线，也是**唯一
  不走传送**的一条：
  `(6, 2) → (1, 2) → (2, 6) → (3, 2) → (11, 2) → (10, 6) → (9, 2) → (6, 2) → (6, 7) → (8, 7)`
  —— 飞行单位无视传送格，自己穿行，所以它最后是直接走到 `(8, 7)`。

### 行进指令：三种节点，只有两种带真坐标

路线里每个途经点都带 `type`。1-7 那种简单图**全是 `MOVE`**，看不出问题；
SR-EX-8 把四种都凑齐了：

| 类型 | 数量 | position 有效？ |
| --- | ---: | --- |
| `MOVE` | 116 | ✅ 真的 |
| `WAIT_FOR_SECONDS` | 75 | ❌ 一律 (0,0) 占位 |
| `DISAPPEAR` | 38 | ❌ 一律 (0,0) 占位 |
| `APPEAR_AT_POS` | 38 | ✅ **真的**，是传送落点 |

把占位坐标当坐标读，地图上会凭空多出一条穿过左下角、终点落在地图外的假路径。

一条典型的路线（route 1）完整展开是这样：

```
入场(2, 2)
  → WAIT_FOR_SECONDS 60 秒      ← 原地待命一分钟，不是走到传送口再等
  → MOVE (0, 2)                  ← 才动身走到左侧传送口
  → DISAPPEAR                   ← 被传送抽走
  → WAIT_FOR_SECONDS 1 秒       ← 传送冷却
  → APPEAR_AT_POS (6, 5)         ← 在中央传送出口凭空出现
  → MOVE (6, 7)                  ← 穿过唯一的地面位
  → 终点 (4, 7)                  ← 左防守点
```

**那 60 秒是入场后就地等待**，这一点很容易读反：38 条路线里 36 条都有这个
60 秒（另外两条是巡逻路线，用的是 1 秒），所以敌人「入场时刻」和「抵达中央
防线时刻」之间隔着大约一分钟。

本工具把这层展开放在 `Route.timeline_hint()` 里：

```python
>>> stage.route(1).timeline_hint()
'等待60s → (0, 2) → 消失 → 等待1s → 传送至(6, 5) → (6, 7)'
```

## 六、还没做的事

- **等待与传送还没并进时间轴**。上面那张表是「入场时刻」；要算出「几点压到
  `(6, 5)`」还得把 60 秒待命、移速、路径长度三者合起来算，这部分没做。
- **移速换算仍未校准**（`moveSpeed` × `moveMultiplier` → 格/秒，与 1-7 同一处
  空缺），所以路径耗时也算不出来。
- **`tile_replace_*` 的触发条件未验证**：12 个可部署格会在什么条件下被改写、
  改写后是否还站得住人，需要对着实机确认。
