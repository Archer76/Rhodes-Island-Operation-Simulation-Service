# 怀黍离敌人能力审计（对照 prts 图鉴）

日期：本轮
起因：博士指示"去 wiki 确认怀黍离其他怪物有没有没拉取到的能力"。

## 一、拉取完整性：21 个号一个不缺

prts 的[活动一览表](https://prts.wiki/w/%E6%80%80%E9%BB%8D%E7%A6%BB)给出
`HSL1`–`HSL20` ＋ `SUI` 共 **21 个图鉴号**。本地 `data/enemydb.sqlite` 的
`enemy` 表按 `index_code` 逐个核对：

```
HSL1 秽   HSL2 除秽   HSL3 蚀    HSL4 去蚀   HSL5 肮    HSL6 厌肮
HSL7 玷   HSL8 勿玷   HSL9 瘴    HSL10 鄙瘴  HSL11 田鼷  HSL12 硬毫田鼷
HSL13 田鼷力士  HSL14 田鼷猛士  HSL15 田鼷飞贼  HSL16 田鼷大盗
HSL17 天桩-甲   HSL18 失控天桩-甲  HSL19 天桩-乙  HSL20 失控天桩-乙  SUI “祟”
```

**缺号：无。库里有、一览表没有的 HSL 号：无。** 另有 2 只非图鉴条目
（`身上的天标`、`身上的天标二`），是机制自己生成的实体，一览表里本来就没有。

⚠ **一处读表陷阱（已澄清）**：`index_code = SUI` 在库里是 **3 行**——
`“岁”`（岁的界园志异）、`“祟”`（怀黍离）、`岁相`（将进酒）。按 `index_code`
取第一行会取错人。怀黍离那一只确实是 `“祟”`（U+795F），能力是
「混沌·每受到一定次数的伤害蜕皮……」，**不是编码病**，是同一个号挂了多只 BOSS。

## 二、能力逐条与消费点

「有没有没拉取到的能力」有两层意思，这里分开报。

### 2.1 拉取层：能力正文都在

21 只的 `ability` 列都能读到完整正文，且与图鉴一致（逐条比对过 秽/除秽/蚀/去蚀/
肮/厌肮/玷/勿玷/瘴/鄙瘴/田鼷/硬毫田鼷/田鼷四兄弟/天桩-甲/失控天桩-甲/天桩-乙/
失控天桩-乙/“祟”）。`ability_fixed` 只有 114/1804 行非空，那是另一条流水线的产物，
不是这一批的缺口。

### 2.2 消费层：**八条能力在两台引擎里都没有消费点**

按"这个能力的影子在代码里能不能找到"扫了一遍（原版 `ak_tactic/` vs Go `rios-sim/`）：

| 能力 | 谁有 | 原版 | Go | 判定 |
|---|---|---|---|---|
| 被击倒后对田地造成病害污染 | 秽/除秽/肮/厌肮 | ✅ `passive_pollut` | ✅ | **已覆盖** |
| 位于受病害污染的田地上时**隐匿** | 秽/除秽/田鼷/硬毫田鼷 | ⚠ 仅公式编译器 | ❌ | **两台引擎都不应用** |
| 位于受病害污染的田地上时攻击转法术 | 蚀/去蚀 | ✅ | ✅ | 已覆盖 |
| 吸收浅水 · 全图近战 · 十字溅射 · 污染地附法伤 | 玷/勿玷 | ✅ | ✅ | **已覆盖（本轮新验，见下）** |
| 重生 · 重生吸污染升防附法伤 | 瘴/鄙瘴 | ✅ | ✅ | 已覆盖 |
| 会攻击周围的阻流阀 | 田鼷/硬毫田鼷 | ✅（装置层 58 处） | ⚠ 8 处 | 部分覆盖；阻流阀一部署就被闸门拦下 |

`formula.py:752`），那是把能力正文解析成公式项的地方，**战斗模拟的索敌逻辑里一处都没有**。
所以两台引擎**都不应用**它 ⇒ **对拍成立**（这是共有的局限，不是 Go 单独的缺口）。

## 三、闸门：**有**敌人侧入口，但它是"字段驱动"的

### 3.1 更正上一版的两处错误结论

⚠ 本文件第一版写「`spec.py` 闸门对敌人侧能力零提及」——**错了**。
`spec.py:127` 有 `bad += _enemy_reasons(sim)`，而且它相当完整：

```
field_why          = {awake_value: 按田地病害值觉醒, hp_drain_per_sec: 持续自伤}
ENEMY_BEHAVIOR_ATTRS = {modes: BOSS 换弱点形态}
+ 「被击倒给可部署装置」在"计划里真放了装置"时单独报（spec.py:435-442）
+ 已接线因此不报的六族：skill_atk_* / passive_pollut / reborn_* / phit_* /
  reborn_summons / pm2_*（spec.py:412-426 逐条有出处）
```

⚠ 我上一版还写「击倒后获得可部署单位：原版 0 处、Go 0 处」——**也错了**。
代码里写的是「可部署**装置**」，我按「可部署**单位**」去 grep ⇒ 空。
这正是本项目那条铁律的又一次复现：**某名字不在这一层，不能推出"没送/没实现"**
（要断言"没有"，得先走完整棵树，或者换一个不需要名字的判据）。

### 3.2 真正的缺口：**字段驱动看不见"没有字段的东西"**

`_enemy_reasons` 的判据是"`EnemyUnit` 上哪个字段非零"。这个设计本身是对的
（不看名字、不看描述关键词）。但它有一类**结构性**的盲：

> 有些敌人能力**在原版里也没拿到字段**，只活在图鉴正文里。
> 字段表里没有它们 ⇒ 闸门对它们**永远沉默**。

而"沉默"与"查过了没问题"在输出上长得一模一样。

⚠ `tools/audit_gate_blindspot.py` 补不了这一块：它扫的是 `sim.X` 的**读写时机**，
是字段级的；`ENEMY_BEHAVIOR_ATTRS` 那种**行为**级的它看不见（所以它报"未登记 0"
是它自己的口径没错，但不等于行为这一类也被盖住了）。

### 3.3 补上的东西：登记 + 自动守卫

`ak_tactic/simgo/mech.py` 新增第三张表 `UNMODELLED_ENEMY_ABILITIES`（5 条），
配套 `tools/audit_unmodelled_abilities.py`。

**判据是两道，都要成立才叫"可以不管"**：

1. **原版战斗层也没建模**：对每条登记的 `py_tokens`，扫 `ak_tactic/battle/*.py` 的
   **代码行**（docstring 与注释行**不计**——`devices.py:25` 那句「将身后一格的浅水
   泵至前方」就是泵站正文的文档字符串，把「浅水」扫成"已实现"是这类工具最容易出的假红）。
   命中 0 ⇒ 两台引擎同样不建模 ⇒ 对拍成立 ⇒ **不该进闸门**（进了是无理由拒跑）。
2. **载体清单对得上**（`carriers` 按**名字**写，不按 enemy_id：同一只怪在不同关里
   有 `_2` 之类的变体后缀）。

**登记表不能只写一句理由就完事**——理由会过期而没人知道。所以每条带
`py_tokens` 守卫：哪天有人把其中一条接进原版战斗层、而 Go 没跟上，它立刻翻红，
要求"要么移进闸门，要么把 Go 补上"。这与 `audit_gate_blindspot.py` 里
`device_deployments` 那条"安全前提会失效"的守卫是同一套手法。

## 四、本轮新增的等效核查：敌方技能出手

`check_mech_parity.py` 的 `HS-EX-7` / `HS-8` 两例被判"咬不到机制"，
真因是**用例里根本没有勿玷**（钩 `_build_enemy` 实测：那个计划刷出来的是
失控天桩-甲 6 / 乙 40 / 除秽 16 / 身上的天标二 16 / 去蚀 3 / 厌肮 3）。

**做等效核查不必改数据**——换成一关真正含这只怪的就行：

* `勿玷` = `enemy_1393_dhele_2`，HS-EX-7 在 **150.0 / 269.0 / 271.0 s** 出场
  （而那份计划的模拟 121.3s 就结束了 ⇒ 永远碰不到）；
  **HS-EX-8 在 t=0 就有 3 只**。
* 新增 `out/plan-hsex08.json`（act31side_ex08，泥岩单人在 (9,4)）。
  对拍不要求这是好解，只要让机制落地。

三项判据：

```
① 一致  原版 2杀 3漏 46.5333s 伤害 8800.0  =  Go  ← 逐项相同
② 反证  把 skill_atk_scale_* 整组清零 → 杀 2→1、用时 46.5333→46.0667、
        伤害 8800.0→8792.0                       ← 判决真的变了
③ 落位  HITOP 9 笔（首笔 t=28.1，raw=600 物理），清零后 → 0 笔
```

⚠ **仪器教训（本轮踩了两回同一个坑）**：`ENEMYATK-BONUS` **不是**敌方技能出手，
是**重生充能附加伤害**（`rebornChargeBonus`）。把 Go 的 `trace` 标签全表列出来确认：
**没有任何一个标签覆盖敌方技能出手**，这一层唯一的可观测量是 `HITOP`。

## 五、结论

1. **拉取无缺口**：21 个号 1:1，能力正文齐全。
2. **有八条能力没有消费点**，其中五条**在两台引擎里都没有**（见 §3.3 的登记表）——
   属**共有的未实现**，不影响对拍，但影响对真实游戏的保真。
3. **闸门有敌人侧入口，但是字段驱动的**：它盖住了六族已接线/未接线的字段型行为，
   盖不住"连字段都没有"的那一类。已用「登记 + 自动守卫」补上
   （`UNMODELLED_ENEMY_ABILITIES` ＋ `tools/audit_unmodelled_abilities.py`）。
4. 敌方技能出手层**已补上等效核查**（HS-EX-8），三项判据俱全。

## 六、⚠ 修正：这五条**不是"暂时碰不到"**，而是**当场就在跑**

第一版写「尚未证实有实际损失：田鼷四兄弟在现有 17 份计划里都没出场」——**错了**。
`tools/audit_unmodelled_abilities.py --plans` 按出怪表逐个计划对了一遍：

plan-hs05   玷→吸收浅水; 田鼷→隐匿; 秽→隐匿
plan-hs06   田鼷/田鼷力士/田鼷飞贼→隐匿/阻挡门槛/受伤奔跑/拆阀高伤; 秽→隐匿
plan-hs09   玷→吸收浅水; 秽→隐匿
plan-hsex01 除秽→隐匿
plan-hsex02 田鼷大盗/田鼷猛士/硬毫田鼷→阻挡门槛/受伤奔跑/拆阀高伤/隐匿
plan-hsex03..06  勿玷或硬毫田鼷→吸收浅水/隐匿; 除秽→隐匿
plan-hsex07 勿玷→吸收浅水; 田鼷猛士→阻挡门槛/受伤奔跑/拆阀高伤; 除秽→隐匿

**17 份计划里有 14 份带着这些未建模能力**（且 `除秽` 在 ex07 里实测刷了 16 只）。

**但这不是对拍的红**：两台引擎**同样**不建模 ⇒ 判决一致成立 ⇒ 四项全归零。
它是**保真的红**：这 14 份计划打赢/打输的算法，与我们其实并不完全知道规则的那场战斗
**是同名不同物**。两者的区别值得写清楚——

* **对拍**问的是"Go 与原版一不一致"，答案是**一致**；
* **保真**问的是"两台引擎合起来像不像真游戏"，这五条上答案是**不像**。

本项目的裁定（`77fce667`）是只在**对拍**这一层设门槛，所以这五条**不进闸门**是对的；
但必须**登记在册并带守卫**，否则"两台一起错"会被下一轮读成"这里没问题"。
