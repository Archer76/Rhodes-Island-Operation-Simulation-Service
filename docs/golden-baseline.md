# 冻结基线：逐套状态与主判据

> ## ★ 先写在最显眼处的一条**信任模型**（第四态「部分覆盖」专用）
>
> **「部分覆盖」是套自己声明的，工具验不了它是否真的覆盖了那么多。**
> 套在 `G.sections([...])` 里**逐段**写「这一段可冻／这一段两侧都是 Python／
> 这一段源码耦合」，工具只做两件事：**① 保证声明可见**（表进基线、check 档每次都印、
> 结论行带上它）、**② 保证它不许当「跑通」**（四分账里单列，**永不进分子**）。
> ⇒ **下一个人不要以为工具验证过覆盖面**——它验证的只是「声明存在、类别合法、被计数」。
> （与 `batch_consumed` 是**同一个信任模型**：声明由套写，工具只管可见与计数。）

**这份文件不干活，它只登记状态。** 状态本身**现算**，不由本文件声明——
本文件里的任何一个数，都可以用下面那条命令重新算一遍，算不出来就是本文件过期。

`check_go_all.py` 登记了第 27 套（**敌方机制**），`--status` 当场就跟着变成 27
——**本工具不抄套表、不写死 26**（写死的分母会在别人加一套之后变成假话）。
★ **基线也可以由别的会话录**：03:00–03:3x 之间另一个会话用同一套工具转了 9 套，
本表按基线的 `script` 栏归属，**它们照样进这一张表**。
★ **取证范围也是活的**：`关卡/敌人` 那几套的清单由 `cached_levels()` 按缓存现算，

`--status` 把它印在表头。**不喂清单的话只会跑那一套的缺省样本（1 关）**——
分母小得误导，正是本仓记过的那种「全绿里那一行看着漂亮、覆盖其实是抽样」。
`--status` 在没全绿时 **rc=1**（所以它是可以接进门的判据，不是一张给人看的表）。
**把这一刀接进验收门不在本会话的产权范围内**（`tools/check_go_all.py` 归上级会话），

★ 两个数的分母**不同、不可并列**：`12 / 26` 的分母是**本次跑的套去掉不适用**，
`12 / 12` 的分母是**跑过默认档那一腿的套**（＝有基线的套）。没基线的套印 `⊘无基线`——
「没跑」与「跑了但不一致」不许混成一个数。

## 1 · 为什么做这件事

博士 2026-09-24 亲自问：**「为什么现在还在和 python 对拍？不是已经由 go 覆盖了吗」**。
逐套量的实测结果是 **26 套里 24 套现跑 Python 当 oracle**。而 2026-09-19 已经裁定过：

> 引擎切换定案：基线全用 Go、Python 仅作历史参考、**门判据＝Go 自身基线漂移即红**。

这条**没落地**。继续吃 Python 的三条代价：

* (a) 有人改了 `ak_tactic/`，**判据的期望值跟着变** ⇒ 两侧同错也判绿；
* (b) `ak_tactic/` 永远删不掉；
* (c) 它量的是「与旧实现一致」，**不是「对」**。

## 2 · 三种模式与退出码

| `RIOS_GOLDEN` | 语义 | 吃 Python 吗 |
| --- | --- | --- |
| 未设 / `0` / `off` | **现状**：现场调 `ak_tactic` 取期望值（对拍）。迁移期默认档，一个字不改 | 吃 |
| `record` | 调 `ak_tactic` 取期望值，**同时**把 `键 → 值` 收下来（由 `--record` 落盘） | 吃（录的时候本来就要吃） |
| `check` | **只读** `fixtures/golden/<套名>.json`；`ak_tactic` 被封死 | **不吃** |

退出码：判据自己的码不动；**`6` ＝ 通道自己的错**（无基线 / 键缺 / 顶层 import 了
`ak_tactic` / 期望值不可 JSON 化 / **脚本从未绑定通道**）。
`6` 的含义是「**这一套还没转**」，**不是「判据红」**——两者压成一个值会同时毁掉两个判读。

**两条防线**（少一条就会有假绿）：

1. **import 拦截器**：`check` 档下 `import ak_tactic` 立即 ImportError。没转好的取期望值点
   当场响，不会静默走回 Python。
2. **绑定断言**：`check` 档的进程退出时，若这一套**从未** `bind()`，以 rc=6 收场。
   ★ 没有它，一套**一个字没改**的脚本在 check 档下会照常跑 Python 并报绿——
   「未转」被读成「已转」。这是本设计的要害。

因此 `check` 档**必须经 runner** 起进程：
`python tools\freeze_baseline.py --run-script tools\check_xxx.py`。
★ 这条**不是靠文档拦的，是靠 `bind()` 拦的**：直跑时缺 runner 标记
（`RIOS_GOLDEN_RUNNER=1`）⇒ 当场 rc=6 并印出理由。
典型触发面：有人把 `RIOS_GOLDEN=check` 导进环境再跑 `check_go_all.py`（它是**直跑**
子进程的）⇒ 4 套真冻结、23 套照常跑 Python 并报绿，而**一张总表上看不出区别**。
所以这条必须在**代码里**堵死，不能只写在文档里。

五个动作：`--list`（套与基线）／`--record`（录，必须显式）／`--check`（只读对账）／
`--status`（主判据）／`--control`（**每套都要做的控制组**，见 §6）。

## 4 · 未转的套：**具名**理由（逐条，不许写「大致都转了」）

未转的套当前都是同一条**程序给出的**具名理由：
`冻结基线防线：套「<脚本>」从未绑定通道（脚本没调 freeze_baseline.bind()）⇒ 未转，rc=6`
—— 即 **一个字还没改**。这不是敷衍的措辞：它是 rc=6 那条防线**现算**出来的，
改一套就少一行。逐套的**实质**理由（能不能冻、冻什么）分列如下：

★ **2026-09-24 03:00 前后，另一个会话用同一套工具又转了 6 套**
（技能／名册／计划／面板／费用天赋／部署费用）——本表按**基线的 `script` 栏**归属：
那 6 套的脚本不归本会话，所以只登记「已转」与读数，**不碰它们的代码**。
同一时刻两个会话在同一棵树上转同一批套，**正是这套工具要能容纳的事**：
套表、清单、分母全是**现算**的，谁转的都不影响那一格的真假。

* **第 2~23 行剩下的（甲/乙类）**：**未核——可冻性尚未逐套验证**。初判只从各自
  `ak_tactic` 的 import 面得出。它们要在各自的节点上被**真录一遍**才算数。
  可能真冻不住的情形只有两类，遇到就具名登记：① 期望值由运行期非确定来源产生
  （时间戳 / 随机 / 文件系统状态）；② 期望值不可 JSON 化。
* **第 24 行 自造规格**：**已落地**（2026-09-24，见 §10 节点八）。裁定落地成：**26 值**
  ＝ 一条 `("query", "fixtures")`（**查询集**：夹具名 → 关卡号 ＋ 夹具内容 sha16）
  ＋ 25 条 `("snapshot", 夹具名, 关卡号)`（**判决四数（除墙钟）＋ `unsupported` 逐位**）。
  冻的是 **Go 自己的产物**（三次提问全是 Go），差分那一路**原样保留**；

### ★ 乙类还要第三样：**输入身份**（对象集是活的）

`关卡` 那几套的取证范围由调用方喂进来（`check_go_all.cached_levels()` 按**缓存**现算），
而缓存在被别的会话逐章取数时会**长大**（实测当晚 72 → **320**）。于是
「现读 ≠ 冻结」有两种**完全不同**的因：

| 因 | 该判成什么 | 码 |
| --- | --- | --- |
| **Go 漂移了** | 判据红，要人去看实现 | `1` |
| **对象集/对象内容变了** | 读数**不可用**，基线该重录 | `6`（印「输入批次对账」） |

这两种红压成一种，后果是本仓记过的那条：**永久假红等于没有判据**——天天红的判据，
最后没人看。所以两个动作：

1. **键里带输入身份**：`("stage", 关卡 id, 该关缓存文件的**内容 sha16**)`。
   只记关卡名是不够的——缓存内容变了就分不出「对象变了」，会拿一份旧内容的期望值
   去比新内容，造出一条**假红**。身份从**数据侧**算（读 json 与文件字节，
   **不 import `ak_tactic`**），所以冻结档也跑得动。
2. **每次跑先对账**：`G.coverage("stage", [(id, sha16), …])` 把「这一批要问的」
   与「冻的那一批」按身份配上，**只比两边都有的**，未覆盖的**不猜**
   （猜＝自己写一份期望值，正是本仓禁止的），并把未覆盖的**具名印出来**：
   `输入批次对账（stage）：这一批 320 个对象 ＝ 覆盖 72 ＋ 未覆盖 248；冻的那一批另有 0 个这次没问`。

★ 另外记一条**可读的**批次记录 `("query","level_batch")`（含每关的 `data_path` 与 sha16），
回答「这份基线录的是哪一批」。它**不参与判定**（真正问哪些对象由调用方的清单决定），
但 `--check` 的「改值」栏会量到它：缓存一变，这里第一个显形。
——**措辞不许含糊**：说成「查询集」会让人以为改它能改分母，那是错的。
⚠ **实测更正**：「敌人」那一套里这条记录**是被消费的**（它参与决定比哪些关 ⇒
改小它冻结档自己就红，rc=6），所以 `--control` 的 P2 会**按实测读数**分两句说
（「是盲区」／「不是盲区，它被消费」）——同一句套用到两套上会有一句是假话。

### ★ 敌人的第三种因：`refs` **是 Go 的产出，又是查询集的来源**

`check_enemy_go.py` 问哪些敌人，是由 **Go 的输出**决定的。所以「现读 ≠ 冻结」
有**三种**因，必须两两分得开：

| 因 | 归属 | 判成 | 码 |
| --- | --- | --- | --- |
| 这一关的**输入**（缓存文件内容）变了 | 调用方/数据侧 | `输入批次对账 … · 输入改动（前 8 关）：…` ＋ `由**输入变化**引起的 ref 差` | `6` |
| **Go 的 `refs` 产出**变了（关卡输入逐关相同） | **Go 侧** | `· ★ **Go 的 refs 产出变了**：+N / −M` ＋ 逐条具名 | `6` |
| 覆盖到的 ref 上**逐字段不一致** | 实现 | 判据红（优先） | `1` |

⇒ 输入身份要记**两侧**：关卡批次（id ＋ 缓存内容 sha16）＋ 每个 ref（`id`, `level`）。
**把「Go 改了 refs 的产出」读成「对象集变了」，就是这一节要堵的那条误导**。
★ 顺带补上一个**原来没有的守卫**：refs **少了**意味着分母缩水，而旧判据只会
「比更少的敌人」然后照样绿——现在它进对账、具名印出。

### ★ 类型还原：JSON 会抹掉 `tuple` / `set`

`json` 把 `tuple` 写成 `list`、把 `set` 直接拒掉。于是**冻回来的值与现场那个值的
Python 类型不同**，而判据里常常有 `sorted(map(tuple, g)) != sorted(cells)` 这种比法
——那一比会**恒不相等**（假红），或者反过来恒相等（假绿）。

⇒ 规矩：**还原写在判据侧，而且两种模式走同一条路**。取法是把现场值**先规范化成 JSON
形状**（`[list(c) for c in cells]`），判据侧再统一还原（`tuple()`）。
**只在 `check` 档还原的话，两档就不是同一个判据了。**
`范围` 是这套形状的第一个实例（`cells` 是 `tuple` 列表、`footprint` 是 `set[tuple]`）。

### ★ 第三态：**不适用于冻结**

判据里的东西有三种，别压成两种：

1. **期望值** ⇒ 冻；
2. **查询集 / 判定·计数口径常量** ⇒ 冻。⚠ 两者性质不同：**改常量未必能翻转判决**
   （实测：「攻击间隔」的 `ASPD_MIN` 只进行使计数，`--control` 的 P1 一开始挑到它，
   报了「没红」；把 P1 限定成只挑**期望值**之后才成立）。常量冻住的目的是
   **让行使计数的口径可复现**，以及让 check 档不去 import Python；
3. **Python 侧自身的自检**（`攻击间隔` 里「`spec.ASPD_MIN` 与 `skill.ASPD_MIN` 必须相等」）
   ⇒ **冻不了也不该冻**：冻住之后两侧同源、**恒等**，是一条不可能失败的判据。
   这一态**显式印出来**（`⚠ 不适用于冻结：……（两侧现在同源，恒真、零信息量）`），
   不许静默当作通过——把它读成绿，就是又造了一条「预先被决定的绿」。

## 6 · 控制组（`--control`，**不是可选项**）

```
python -X utf8 tools\freeze_baseline.py --control <套名…>
```

本仓规矩：**控制组没红时工具自己吼出来并 exit 1**（没有反向守卫的绿是零信息量的绿）。
四个探针，各堵一种洞：

* **P1 · 改一个期望值 ⇒ 必须判红**。证明「**冻的值真的是 oracle**」，
  而不是「读了个文件、判决照旧看 Go」。
* **P2 · 查询集删一个 ⇒ 冻结档看不见（盲区，读数照印）**，
  **P2b · `--check`（拿现读的查询集对账）必须看见**。
  两条合起来才说明分母缩水有补偿控制、且补偿控制真的管用。
* **P3 · 删掉一个对象的全部键 ⇒ 必须判成「对象变了」**（rc=6 且印「输入批次对账」），
  **不能**读成「Go 漂移了」（判据红 rc=1）。
* **P3b · 少喂一个对象（反方向）⇒ 必须判成「分母缩水」**（rc=6 且印对账）。
  缓存被清时就是这个形状（本仓真出过：`git worktree remove` 穿透 junction 删过
  主仓 `data/`）——**分母缩水而判绿**才是灾难。
* **P4 · 同一对象集、内容变了 ⇒ 必须判成「内容变了」**。
  它与 P3 是**两个不同的诊断**：P3 改的是**对象集**（多/少一个对象），
  P4 改的是对象的**内容**。两者都 rc=6，但**印出来的话不一样**，
  而下一个人要靠那句话决定「重录」还是「查对象集」。

## 7 · 封死的边界（已知，不假装没有）

**拦截器只盖得住本进程的 import。** 判据若 `subprocess.run([PY, "-m", "ak_tactic", …])`
去取期望值，`sys.meta_path` **看不见它**。与其把这句写成口号，不如把它变成一个数：
`check` 档下 runner 会给 `subprocess.Popen` 打一个探针，把**命令行里提到 `ak_tactic`
的每一次 spawn** 记下来并印在结论旁。实测（未转的「命令面」套）：

```
★ 冻结档下 spawn 过 2 个子进程，其命令行里提到 ak_tactic：
    python -X utf8 -m ak_tactic stage main_02-07
    python -X utf8 -m ak_tactic stage act31side_01
```

⇒ 每转一套都要回答一句：**这一套的取数口是不是全走 `G.expect()`**（spawn 计数为 0）。
被测方本来就是 Python CLI 的套（命令面）不算违规——**它测的是 Python，不是从 Python 取期望值**。

### 7.1 ★ **缓存长大 ⇒ 7 套的查询集已经过期（基线该重录）**（2026-09-24 现算）

**这是本设计里唯一一个会自己变坏的量**：乙类套的查询集来自**调用方按缓存现算的关卡清单**
（`check_go_all.cached_levels()`），而缓存在别的会话逐章取数时会**长大**。
实测：**320 个键（159 份内容）→ 562 个键（388 份内容）**，`#s` 变体与新章节一起进来。

**便宜探针**（不跑判据、不跑二进制，只比「冻的批次记录」与「现读 `cached_levels()`」）：

| 套 | 冻的批 | 现读 | 状态 |
| --- | ---: | ---: | --- |
| 关卡／关卡静态／寻路／敌人／格表／部分规格 | 320 | 562 | **该重录**（现读 +242） |
| 机制规格 | 320 → **562** | 562 | **已重录**（2026-09-24，587 值，523.7 s） |

⇒ **`--check` 在这几套上会 `rc=1`，而那不是「Go 漂移了」，是「录的是哪一批对象」变了**
（`rc=6` 与 `rc=1` 必须分开的那条纪律，在这里被**同一批对象集**触发）。
**处置＝显式重录**：`python tools\freeze_baseline.py --record <套名>`，会印出覆盖了谁。
⚠ **不重录也不会让闸门变红**：`check_go_all` 跑的是**默认档**（现读 vs Python），
冻结档那一腿只问**冻住的那批**——所以这是一个**不会自己喊出来的**过期，
必须靠上面这张表定期现算。**未重录的 6 套已具名登记，不假装没有。**

明明有 `sha16`。那句话是**结论**（只在 `_p4_target()` 找不到之后才成立），
接错分支就变成一句与事实相反的话。**输出的每一句都要是真的。**

1. **期望值是一整块**：一个键的期望值是**一整份打法里每条部署的练度列表**
   （不是一个标量），所以「条数不一致」这条旧判据**在两种模式下都照跑**——
   这正是把它整块冻住、而不是拆成逐点的理由。
2. **失败也是期望值**：本套有一支判据是「**两边都拒**」（`both_refused`）。

3. **对账要把所有会变成键的对象都算进来**：本套的键来自**两组**对象

**★ 顺手修掉一处机制缺陷（这一处比练度本身更要紧）**：练度第一版在 `main()` 里有一行
**只用来打印**的 `import ak_tactic.verify`，冻结档下拦截器当场响 ⇒ 但那个 ImportError

同一个数。现在拦截器响过会记一笔（`_BLOCKED`），runner 的收尾据此退 **rc=6** 并印
「**未转完**」。实测未转的套仍是 rc=6（回归通过）。

## 9 · 基线里的身份栏位（不是元数据噪声）

`fixtures/golden/<套名>.json` 每条都记：

| 栏 | 为什么必须有 |
| --- | --- |
| `suite` / `script` / `script_sha256_16` | 脚本改了而基线没重录 ⇒ 对不上，`--check` 报「该重录」（**节点二实测到了一次**） |
| `recorded_at` | 判「这份基线有多旧」 |
| `instrument.sha256_16` | ★ 不记仪器，将来绿红翻转时没人能判是 Go 变了还是仪器换了（见 `docs/baseline-flip-list.md`） |
| `python.version` / `git_head` / `ak_tactic.sig16` / `ak_tactic_dirty` | ★ **「用哪个 Python 版本、哪次 HEAD 录的」是基线的身份**：没有它，将来对不上时没人能判是 Go 变了还是 Python 变了。脏名单单独一栏——**脏的那几行正是期望值的来源** |
| `values` / `keys_readable` / `n_values` | 值 ＋ 人读的键 ＋ 条数（条数在 §6 的残余风险里是锚之一） |

`--record` **必须显式点名**；覆盖已有基线时先打印**被覆盖文件的完整录制身份**，
再把「新增 / 消失 / 同键改值」三栏逐块报出（本仓记过：生成物被静默覆盖，没有历史）。

## 10 · 换基线的当天必须登记

本次迁移是**换尺子**（期望值来源从「Python 现场」换成「冻结文件」）。
按 `docs/baseline-flip-list.md` 的规矩：**换尺子的同一个提交里就要写下哪些条目因此不红了**。

另：本次迁移**不改变任何判据的比较逻辑与结论**，每一套在转好的那一刻，
默认档与冻结档**必须同时绿**（§8 节点二那张「改前 vs 改后」表就是这条的证据）。

### 节点七 · 第四态「部分覆盖」（工具）＋ 出怪规格（第一套 partial）

**为什么会有第四态**：`出怪规格` 是**捆绑判据**，11 段里 4 段**不适用等值冻结**：

| 段 | 类 | 为什么 |
| --- | --- | --- |
| §2 替身等价性 | `python_both` | `harness()`（Python）↔ `spec["spawns"]`（也是 Python） |
| §4 species_provider 敏感性 | `python_both` | `a` ↔ `b` 两侧都是 `harness()`——**它是控制组** |
| §5 `armed_moved` 控制组 | `python_both` | `w_false` ↔ `w_true`，两侧都是 Python |
| §6-源码 | `source_coupled` | `PILE_MARK` 现推 ＋ `ast` 读 `ak_tactic` 源码文本 |

冻那三段＝**让同一份冻值跟自己比**（恒等假绿）；冻第四段＝每次改源码都该重录（永久假红）。

**四条规矩与实测**：

| 规矩 | 落地 | 实测 |
