# 干员机制补全标准工作规程与流程规范

> 本规程规定在 `ak-tactic`（尤其是 Go 仿真引擎 `rios-sim`）中对干员进行完整机制建模与接入模拟的标准作业流程。
> 今后每位干员的机制补全均须严格遵守本规程，杜绝臆测与静默降级。

---

## 〇、基本原则与纪律

1. **零近似原则**：禁止用简化数值或粗糙期望替代真实机制（如「折抵闪避为减伤」「忽略位移直接原地攻击」等一律禁止）。未实现的机制必须具名抛出占位或报错，不得假装通过。
2. **证据链与数据隔离**：原始数据来自游戏数据源（`excel/character_table.json`、`skill_table.json`、`battle_equip_table.json` 等）与本地库 `data/akdb.sqlite`，规格层只读真实数据并提取证据链，不手写硬编码数值。
3. **分层解耦架构**：
   - **规格层（Spec）**：负责数据提取、版本与等级验证、潜能/精英/模组分支、证据链（Raw JSON）保存。
   - **配置层（Config/Blackboard）**：严格解析黑板键，未知/未消费的键必须显式审计，禁止静默忽略。
   - **实体与几何层（Entities / Geometry）**：处理召唤物、弹道、攻击范围、碰撞与位移。
   - **战斗与效果层（Combat / Effects）**：处理攻击多连击、伤害公式、弱点机制、Buff/闪避/沉默状态机。
   - **技能生命周期（Skill Runtime）**：SP 充能、起手瞬发效果、持续时间与技能后 Buff、弹药/库存消耗。
   - **模拟器接入（Integration）**：在 `OperatorOut`、`operators.go`、`sim.go` 中完成挂钩，并验证与解算器的完整协同。
4. **测试与可测性保证**：每个子模块必须配有独立的单元测试（`*_test.go`），且必须包含：
   - 精英/潜能/技能等级/模组等级的全矩阵覆盖测试。
   - 核心机制的数值与状态机单测。
   - 边界异常断言（无效时间、缺失对象、非法参数时具名报错）。
   - 集成测试：能够正常构建 Operator 并在 `sim.go` 的战斗循环中执行。

## 一、标准补全五步法

```
【第一步：数据取证与口径审计】
  ├─ 查阅 gamedata 原始数据（excel 战斗表）与 akdb
  ├─ 提取干员特性、天赋（各阶段与潜能）、各技能（1~10级）、专属模组分支
  ├─ 盘点黑板键全量列表，比对现有模拟器支持情况
  └─ 撰写干员机制口径文档（docs/<char_id>-mechanics.md）

【第二步：规格与配置构建（Spec & Config）】
  ├─ 建立 <name>_spec.go 与 <name>_spec_test.go
  │   └─ 实现 SourceSpec、原始证据 Evidence、分支校验与占位标示
  └─ 建立 <name>_config.go 与 <name>_config_test.go
      └─ 严格解析 Blackboard，每个键建立强类型映射，禁止键泄漏

【第三步：领域机制与状态机实现（Domain Modeling）】
  ├─ 实体/弹道/几何（若有召唤物、移动、剑气弹道等）
  ├─ 战斗状态与判定（多连击、弱点伤害、异常状态、护盾/闪避）
  └─ 技能生命周期（充能、开启、打断、结束、后续状态）

【第四步：主循环接入（Engine Integration）】
  ├─ 在 operators.go 中接驳 BuildSourceSpec 与 OperatorOut 字段
  ├─ 在 sim.go / combat 循环中接入天赋钩子、技能触发与特殊实体 Tick
  └─ 确保 wire.go 与 buildspec 单一入口序列化兼容

【第五步：全量回归与封板验收】
  ├─ 跑通当前干员的所有单测
  ├─ 跑通 rios-sim 全包回归测试（RIOS_DATA 与 RIOS_DB 环境断言）
  └─ 在 docs/<char_id>-mechanics.md 记录实现状态与审计台账
```

---

## 二、审计与检查清单

每位干员在宣告完成前，必须对照以下清单逐项勾选：
- [ ] 所有技能的黑板键均有归宿（已消费 / 具名裁定不影响战斗）。
- [ ] 潜能 1~6、精英 0~2、技能 1~10 级、模组 0~3 级在规格层可正确映射。
- [ ] 技能范围（Range ID）与攻击间隔（Base Attack Time）符合设定。
- [ ] 特殊机制（位移、弹道、沉默、弱点、闪避、连击）均有运行期可观测的状态变化或事件日志。
- [ ] `go test ./...` 全绿，无数据缺失假红，无静默降级假绿。
