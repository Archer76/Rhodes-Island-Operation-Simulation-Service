## 三、落点与实施顺序

**落点：Go（`rios-sim/`）。** 理由有两条，都是已经发生的事实而不是偏好：
默认模拟器已由博士裁定切到 Go（见项目记忆）；Python 的 `ak_tactic/battle/` 正被
另一会话逐轮摘除（`AK-TACTIC-进度.md` 3.29–3.42）。数据流是
**Python 解析/规格（`ak_tactic/simgo/spec.py`）→ Go 引擎 → 对拍**，所以每条机制
要动三处：规格带字段、Go 消费、自检/对拍给判据。

| 优先级 | 条目 | 理由 |
|---|---|---|
| P1 | 寒冷（攻速 −30 ＋「再次寒冷→冻结」）、抵抗（异常时长减半、麻痹每 5 秒流失 1 层） | 改的是**已有的控制链**（Go 已有冻结/眩晕/停顿/束缚），一条通则覆盖大片引用 |
| P1 | 冻结期间「敌方法术抗性 −15」 | 冻结已在 Go 里，缺的只是这条数值 |
| P2 | 脆弱 / 元素脆弱 | 伤害公式的一环（`受到…伤害提升相应比例，同名取最高`） |
| P2 | 元素损伤体系：神经 / 侵蚀 / 灼燃 / 凋亡 / 狂躁 ＋ 元素抗性 | 五条共用一个"累计到 1000 触发"的状态机＋五套结算；工程最大 |
| P3 | 麻痹、战栗、恐惧、沉睡、浮空 | 控制类补全，各自有独立判据（打断本次攻击 / 被阻挡后不能普攻 / 四散逃跑 / 无敌且无法行动 / 转空中单位） |
| P4 | 自身状态：隐匿、迷彩、起飞、折射、近地悬浮 | 前四条在**我方**单位上，折射与近地悬浮是**敌人侧独有** |

## 四、诚实登记（不许装成 0）

* **寒冷 —— Go 侧已落地**（2026-09-19，`rios-sim/sim.go`）：
  `coldASPDDown = 30` ＋ `enemy.coldTimer` ＋ `enemy.interval()`
  （`基础间隔 × 100 / max(20, 100−30)`）＋ `applyCold()`（已在寒冷中则转冻结）。
  守卫在 `rios-sim/status_test.go`（5 条）。**没有寒冷时公式恒等于原值**，
  所以这次补数一位都不动既有对拍基线——自检里把这条钉死了。
* **寒冷 —— 还没有来源接线**：`applyCold()` 目前**没有任何调用点**。
  原版 Python 侧同样从未给 `cold_timer` 赋过正值（它的注释就写着"降低多少我拿不到"），
  所以两台引擎在这一条上都是"机制有了、来源没接"。真要接的是两处：
  ① 天赋「圣山的祝福」每次受伤给攻击者 1.5 秒寒冷（黑板 `cold`）；
  ② 离开积雪的 5 秒寒冷（原版 `talents.py` 明记"未建模"）。
  **接之前要想清楚一件事**：接了就会改变对拍基线，而这属于"把原版没有的行为加进 Go"，
  得博士点头。
* **冻结法抗 −15 —— Go 侧已落地，但判据订正过**（`enemy.res()`，动态判据：冻结一结束
  就恢复）。敌人作为受击方的三处结算都已改走 `res()`（普攻/技能主结算、机制物理伤害），
  不会再有人直接读 `spec.RES` 绕过它。
  **订正内容（2026-09-19）**：起初按 tooltip 词典的「***敌方*被冻结时**，法术抗性-15」
  实现，即看**目标阵营**；PRTS `可抵抗状态` 页写明「**仅友方冻结**会令目标法术抗性-15
  （直接加算），**与被冻结的是否是敌方单位无关**……敌人施加的均为敌方冻结」——
  看的是**施加方**。已改为形别判据 `applyFreeze(secs, friendly)` ＋ `freezeFriendly`，
  并配**反向守卫** `TestHostileFreezeGivesNoResDown`：敌方冻结照样冻住、但**不给 −15**。
  本项目现有两条冻结来源（圣山的祝福、积雪）都是干员给的，所以既有基线一位不变。
  已知近似：混合来源时按"剩得更久的那一笔"定形别；精确做法要按来源各记一份计时器。
* **抵抗 —— 公式层落地（未接线）**，2026-09-19：`rios-sim/resist.go`，
  守卫 5 条在 `rios-sim/resist_test.go`。口径来自 PRTS `可抵抗状态` 页，
  **不是**"时长减半"：`状态实际持续时间 = 原持续时间 × 可抵抗状态生效时间倍率`，
  即把计时器的**流逝速度**乘以 `1/倍率`——页里晕眩的例子是每帧扣 2/30 秒而非 1/30 秒。
  ⚠ 两者对"还剩多久"等价，但对**定时触发的效果**不等价：同页明说"每秒受到一次法术伤害"
  在抵抗下会变成"每 0.5 秒受到一次法术伤害"，**总伤害翻倍**。按"砍一半"实现，
  这一路会静默丢掉，而且从时长上看不出来（守卫专门用"走完它花了多少帧"去钉）。
  另有「站内标注为**固定**触发间隔的不会受影响」一条——属数据问题，不在这里一刀切。
  麻痹那条（每 5 秒流失 1 层 → 抵抗下 2.5 秒）是**推导**，PRTS 没有直接写，已单独标注。
  **未接线**：没有调用点（现有控制链里还没有可抵抗状态在跑）。
* **⚠ 一条假设需要裁定**：**寒冷转冻结之后的时长**。tooltip 只说"会变为冻结"、
  **没给时长**，实现按"触发那一次的秒数"取（`applyCold`）。这是假设不是定论；
  要改成别的口径，只改那一处。**这一条目前只登记在本文件**，
  还没进 `docs/uncertainties.md` 的待裁定清单（那份是生成物，登记要动生成器）。
* **元素损伤 —— 五条全部落地（机制内核）**，2026-09-19：`rios-sim/element.go`
  ＋ `docs/element-damage.md`（权威口径来自 PRTS `元素` 页，**不是**工具的 tooltip 词典——
  词典那五段全是"我方角色受到的效果"列，对敌人用会每档都错）。含元素值（EP，默认 1000、
  领袖 2000）、损伤抵抗式、爆条与爆发冷却（**降到 0 触发 → 冷却期间对所有元素免疫 →
  结束整体归满**）、两列各五行的爆发效果表、`resolveElementDamage`（元素抗性那一档，
  与法术同式、无穿透、**不接闪避**）。守卫 7 条在 `rios-sim/element_test.go`。
  **同样尚未接线**（原版零实现），接线三步写在 `docs/element-damage.md` 第五节。
* **折射 / 近地悬浮**：干员侧引用为 0，属纯敌人侧机制，仍未建模。
* 本表的「引用数」是**首过**统计，词在正文里出现即计；某条真要判定"这一关会不会
  走到"，必须回到具体关卡与出怪表，不能用这个词频代替。
