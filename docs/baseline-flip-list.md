# 因换基线而转绿、但未归因的条目（换尺子当天必须登记）

**为什么单独立一份**：**换基线会把一批红一次性变绿**。这批条目**没有被修复，只是换了参照物**——
而**换尺子当天不登记，一周后就没人知道那条曾经红过**。本项目在 2026-09-19 把基线从
「原版 Python 模拟器」改成「**Go 自己**」时，正是这一批最容易被丢掉。

## 分母（"N 条"必须带名单）

本清单的遍历范围＝**判据集 `fixtures/*.json` 里的 19 份作业**（名单与各 sha16 见

## 第 1 条的三重未解（一条比一条难）

1. **量的差解不掉**：`frozenResDown`（冻结期间法抗 −15）**不足以**解释 35 杀之差与 8 人全灭；
   首个漏怪事件两边**同在 t=96.4**（厌肮）⇒ 分歧在**阵亡与后续出怪**，不在开头。
   `won=True` 且 `timed_out=False` ⇒ 814 秒是**自然打完**，不是被 `max_time` 截断。
2. **输入身份待查**：本行的读数用的是 `roster_max_modelled`（满练度名册），它**来自旁支检出**；
   记忆里有「满练度名册把 HS-EX-8 从打不过变成 814 秒胜利」——**很可能差在名册，不在引擎**。
   ⇒ **名册身份查清前，禁止把这条归因到源码。**（PM 2026-09-19 23:22 定）
3. **仪器身份（2026-09-19 23:2x 新增的一层）**：同一条 `--check`、同一份基线、同一批 19 份，
   **只差 `RIOS_SIM_BIN` 就绿红翻转**：未钉 ⇒ 落到共享 exe（sha16 `b3e4d6b1565d63b4`，构建于
   **19:08**，落后 16 个提交）⇒ `hsex8_max` 报 **814.0333s/591046.1**；钉住当轮私有构建
   （sha16 `b88b28ce6d0ca14f`，**22:13**）⇒ 报 **221.6667s/282276.8**、**19/19 全绿**。
   ⇒ 这一行历史上出现过的"红"与"绿"，**都可能只是仪器不同**。

## 机制：为什么"换了参照物"比"修好了"危险

被判据判红的条目会**逼人去看它**；而被换尺子变绿的条目**安静地消失**。
所以本清单的规矩是：**换基线的同一个提交里，就要写下"哪些条目因为这次换尺子而不红了"**，
并逐条给出**它被修复的证据**或**"未归因"这四个字**——**没有第三种写法**。
