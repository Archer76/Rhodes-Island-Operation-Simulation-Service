这是**全称断言**，取证范围必须跟着走：**在本批扫描的 126 关里**没有出现「清单非空且痕迹全空」；
它不能说「这套引擎不存在静默失效的机制」，只能说「这条路线 × 这套合成计划没把它们逼出来」。
★ 另外要提醒一句与前两批**不同形**的点：本批 **B 层 won=true 的关是 0 关**，
所以「零痕迹」在这里不是靠「赢了的关本来就没机制」解释掉的。

### 5.4 ★ 本批最重要的一个读数：`easy_XX-YY` 与同名 `main_XX-YY` **同一仪器下逐位相同**

这是一个**同仪器、同计划**的对照（不跨批）：把 102 个 `easy_XX-YY` 与同名 `main_XX-YY`
用**本批这一枚 exe**、**同一份合成单干员计划**各跑一次（只读，不写仓库内任何文件），比较：

| 比较对象 | 对数 | 判决四数逐位相同 | 痕迹标签逐位相同 |
| --- | --- | --- | --- |
| `easy_XX-YY` vs `main_XX-YY` | 102 | **102 / 102** | **102 / 102** |
| （正对照）活动 `#f#` vs 同名基础档 | 8 | **0 / 8** | **0 / 8** |

★ **正对照是必要的，否则「逐位相同」可能只是尺子钝**：同一批、同一仪器下，
8 对活动突袭档 `#f#` 与同名基础档里**逐位相同的有 0 对（判决）／0 对（痕迹）** ⇒ 这套比较**有区分力**。
而 102 对 `easy`／`main` 全部逐位相同 ⇒ **简单模式这一档的难度没有进到读数里**。

**成因未核**（本台账不下这个结论）：可能是 easy 档的难度标签没有下传到构建，
也可能是 easy 与 main 在这套数据里本就同内容。要定因得去查难度字段的下传路径。
**但它至少说明：拿 `easy_XX-YY` 当「同一关的低难档」来读三层，读到的与 `main_XX-YY` 是同一个东西。**

### 5.5 读表时另外必须知道的事

① **有 2 关的 `elapsed` 是撞关卡时限撞出来的**：`easy_09-04`、`easy_14-11`。
实测这几关的 `spec.max_time = 900`，判决里的 `elapsed ≈ 900.03s` 就是上限本身 ⇒ 判决**由时限决定**。
对照：第一批的 `main_09-04`／`main_09-04#f#`、第二批的 `main_12-14`／`main_14-11` 也各撞上限——
本批撞上限的 `easy_09-04`／`easy_14-11` 正是它们的主线同名档，形状一致。

② 本批 **B 层 won=true 是 0 关**（126 关全部判负）。
⚠ 这**不是**「活动关都过不去」的结论：本批全部是**合成单干员计划**，而**没有一关有作业夹具**，

   `non-main (activity/other)`，并在 JSON 里加了 `scope_note` 记明此事；**读数行一字未动**。
