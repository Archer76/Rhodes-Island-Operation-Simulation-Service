## 二、口径

### 1. 关卡集口径

* 本批 = `tools/check_go_all.py:cached_levels()` ∩ `^main_(1[1-7])-` 
  = **第 11～17 章在盘上缓存里可达的全部关卡 id，共 172 个**。
* 其中普通档 **127 个**，险地档 `#s` 变体 **45 个**，突袭档 `#f#` 变体 **0 个**。
* ★ **变体与同名普通档是两套分母，不许并列**：同一关的普通档与 `#s` 档是两个关卡 id，
  判「覆盖率」时说清用的是哪一套。本台账按**关卡 id** 报（三层读数是一次一次构建跑的）。
* 与第一批合起来 = 第 0～10 章的 262 个 id ＋ 本批 172 个 id；**但合起来也不许当成一个分母**，
  理由同上再加一条：**两批的仪器不同**。

### 2. 有夹具与没夹具：合成计划这一刀

* 有作业夹具（`fixtures/plan-*.json`，经 `level_mech_inventory.plan_fixture` 判定）的：
  **一关都没有**（本批 172 关在 `fixtures/` 里全无对应作业夹具）。
  ⇒ 本批**没有任何一关是「用真夹具跑出来的」**，全部是合成计划。
* 其余 **172 关没有作业夹具**，按博士裁定一律加 `--synthetic-plan`：
  用一份**明确标成合成**的单干员计划（克洛丝，精英一 55 级，位置 [1,1]，技能 0）硬跑。
* ⚠⚠ **合成计划关的 B 层判决四数只说明「这一关跑得动」，不说明「这一关有人能过」。**
  合成计划关的 C 层也只说明「这些机制在这条路线上被走到过」，不是这一关的机制全覆盖。
* 不加 `--synthetic-plan` 时入口会**大声拒跑**（`⊘ 不适用`，rc=3）；本批 `⊘` 计 0 关，
  是因为无夹具的关全部按裁定改用合成计划硬跑了。**这个 0 不代表拒跑分支没被验过**
  （第一批已单独验过：`python tools/level_full_sim.py main_00-02` ⇒ rc=3）。

### 3. 三层各自的判红形状

| 层 | 读什么 | 判红 |
| --- | --- | --- |
| A 算得出 | `buildspec` 的顶层键是否造齐（本批一律 20 个，见 3.1）；`missing_keys`／`gated_keys` | 缺键、或被闸门/难度修饰层**拒跑** |
| B 跑得动 | `sim` 的判决四数（won／life／kills／leaks）＋ elapsed | 跑不起来、或判决缺字段 |
| C 机制真被行使 | 机制清单（数据侧现算）与运行期痕迹**并排** | 清单里有、痕迹里一条都没有 |

★ C 栏只报**读数**（痕迹标签种数／笔数、清单键数），**恒等与否由人判**——工具不替人下这个结论。

### 3.1 ★ 规格顶层键数 19 → 20：这是**仪器换的**，不是章节差的（已实测）

本批 A 层通过的 171 关，`buildspec` 顶层键数**一律是 20**；而第一批（`docs/level-sweep-main.md`）记的是一律 **19**。

为了不让这个差被误读成「高章节多一个键」，**用新仪器把第一批的一关重跑了一次**（只读复查，
没覆盖任何既有产物）：`main_00-01`（真夹具）⇒ 新仪器下 `n_keys=20`，比第一批多出来的键是
**`retreats`**——与交付方说的「换 exe ＝ 撤退机制 ＋ 安德切尔口径更正」对得上。
⇒ 结论：**19→20 是换仪器带来的**，两批键数不同**不代表关卡集有差**。
同一关的判决四数（won=True／life=20／kills=11／leaks=0／elapsed=75.13）与痕迹七种，
与第一批记录**逐位相同**——换仪器在这关没改读数，但改了规格面。

「0 条痕迹」先要证明**那次跑成功了**。本台账只有 `B ok=True`（判决四数都在）的关进入 C 层零痕迹的判定范围。

### 5.4 读表时另外必须知道的事

① **`#s` 险地档的难度确实下传了**（不是标签空转）。45 个 `#s` 与同名的普通档逐对比较判决四数，

② **B 层 won=true 的只有 1 关**：main_14-20。
这 1 关里用真夹具的 **0 关**；其余是合成计划在漏怪耗命口径下的「赢」。**这一栏不能当作通关能力的读数。**

④ **有 2 关的 `elapsed` 是撞关卡时限撞出来的，不是自然结束**：`main_12-14`、`main_14-11`。
实测这几关的 `spec.max_time = 900`，判决里的 `elapsed ≈ 900.03s` 就是上限本身。
⇒ 这些关的 B 层四数**由时限决定**，换一份计划照样会在 900s 处截断；
读的时候不要把它当成「这关自然打满 900 秒」。（顺带：第一批的 `out/level-sweep.json` 里也有 2 关同样撞上限——
