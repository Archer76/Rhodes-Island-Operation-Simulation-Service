### 我做了什么、没做什么

**做了**：`EnemyUnit.cold_timer`（剩余时长）与 `EnemyUnit.freeze_timer`（限时

## 十、位移：规则与接线都已落地（2026-09-18 起本节不再是欠账）

**规则层**在 `ak_tactic/battle/displace.py`；**接线**在 `EnemyUnit.displaced`
（守卫 `check_battle` 第 `[26]` 节）。原先"没有地方可以落"的症结是位置由
`point_at(route, progress)` 算出、没有「脱离路线」这个概念——解法是加一个**并列**
坐标，而不是改掉 `progress`。

仍然欠的（都不在本批范围内）：

* **弹道时间**没接：现在是瞬时推开，`displace.push_time` 拿到了但没用上；
* **拉动**没接：`attract` / 「诱导」是另一套机制（圣聆初雪技3 用的是它）；
* `force` 没进 `SkillEffects` 的分类表，是从 `blackboard` 直读的；
* 敌人**重量**只在 gamedata 的 `massLevel`，敌人库里没有这一列。

位移的**规则**已经查实并落地（`ak_tactic/battle/displace.py`，出处 PRTS
「推与拉」与「游戏数据基础#力度对应表」）。落不下去的不是数，是**表示**。

### 规则的结论（有出处，可直接用）

- **受力等级 = 力度等级 − 重量等级**（「力度对应表」与目标重量的**差值**）。
- 推力**作用时间瞬间**，等价于给目标一个"受力×1s"的动量；之后是匀减速滑动。
- **弹道类与特效类不同值**（命中帧多一帧以初速度的失衡位移），0 级受力是
  1.6958 格（弹道）对 1.56247 格（特效）。
- 方向力的**特殊修正**：夹角 > 45° **或** 距离 < 0.25 格 → 改判径向力且
  **受力等级 −2**。是**或**，不是且。
- 拉力 0 级及以上是**拉至身前**，不是走固定格数。
- 位移是**连续值**（1.6958 格），不是整数格。

### 落不下去的地方

敌人位置是从**路线进度**算出来的：`ak_tactic/battle/unit.py:828`
`self.position = point_at(self.route, self.progress)`，走分段计划时另有
`_advance_legs`。也就是说——

**"敌人偏离路线"这件事在模型里没有表示。** 把 `position` 改掉，下一帧
`point_at(route, progress)` 会把它算回原处；把 `progress` 改掉，等于"沿路线
后退"，只对**与路线反向的推力**成立，横向推力（把她沿部署方向推出去）根本
表达不了。

要真正接线，得先给敌人加一层"偏离路线的位移"，或者把行进模型换成
2D 位置 + 重新寻路。**这是架构改动，不是补一个字段**，所以我没有把
规则硬塞进现有的 `progress` 里——那样会在横向推的场合静默算错，而
"看起来推动了、结果不对"比"没实现"更难查。

### 什么时候值得动

等真有一份作业**靠位移通关**时再动（地穴推人、推回拆火）。在那之前，
规则层留在库里、逐值有守卫（`check_battle.py` 第 `[20]` 节，27 条），
接线时直接可用。

### 与它无关的一个坑（免得白找）

敌人**重量在 gamedata 里**（`gamedata/enemy.py:507` 的 `weight`，取
`massLevel`），**敌人库 `data/enemydb.sqlite` 里没有这个字段**——表结构里
只有图鉴字段（`page`/`name`/`category`/…），没有任何质量或重量列。
去 enemydb 找会白找一轮。

## 十一、屏障：叠加与衰减的规则已查清，但实现先不做

**规则本身不欠账**（2026-09-18 查证，守卫 `check_battle` 第 `[25]` 节）：

* 屏障**会叠加**，上限**每个技能各自**——varkis技2 `max_hp_ratio 1.0`、
  cairn技2 `shield_max_hp_ratio 0.9`；
* 一次授予**可以超过最大生命的 100%**——gravel技2 `hp_ratio 2.5`（250%）。
  **因此不存在"统一按 100% 封顶"这种写法**；
* **衰减**是另一回事：gravel技2 `duration 10`、morgan技2 `shield_duration 6`、
  cairn技2 `buff_duration 10`。

**欠的是实现**，而本批**不需要**它：十位干员里只有电弧技1 与机械师技2 给屏障，
两者都没有上限键与衰减键、都写「持续至技能结束」、一次激活只授予一次，所以
`OperatorUnit.grant_barrier` 现有的 `max` 与 `sum` **完全等价**。

**什么时候必须动**：那两个技能里出现上限键或衰减键时。守卫 `[25]` 钉着这条，
它会先响。

**另需注意**：`hp_ratio` 这个键**同名反义**（见计划里「同一条判据的坑」），
屏障的判据只能按渲染后的描述取，不能按键名取。

## 十二、撼地者特性的**溅射形状**取不到，天赋1 因此卡在第一格

怒潮凛冬天赋1「汹涌怒火」要落地，前提是先有**特性溅射**：

> 特性（撼地者）：攻击使**目标周围的其他敌人**受到相当于攻击力 **50%** 的
> **群体**物理伤害。
>
> 天赋1：特性溅射造成的物理伤害**提升 24%**（黑板 `damage_scale: 1.24`），
> 且**溅射到的每个高台**对周围四格所有地面敌人造成相当于攻击力 24%
> （潜3 起 27%，黑板 `attack@splash_atk_scale`）的物理伤害。

**已经确定的**：50% 这个底数在特性正文里；`damage_scale` 是天赋的倍率
（50% × 1.24 = 62%）；高台可判（`gamedata.stage.Tile.is_highland()`，
`height == "HIGHLAND"`）；"地面敌人"可判（敌人侧有 `is_flying`）。

**还没确定的**：**"周围"到底是哪几格**。

* 本地库**没有**这个字段——`operator_attr` 的列里没有 splash（列清单见
  `PRAGMA table_info(operator_attr)`），`operator.raw_json` 里也搜不到
  `splash` 字样；
* 干员侧的普攻目前**根本没有溅射实现**：`sim._operators_attack` 里是
  `for target in targets:` 逐个结算，没有"目标之外的敌人"这一路；
  `sim.py` 里带 `splash` 字样的字段（`skill_atk_cross` 等）全在**敌人**侧。

**因此这里是一个"必须先查外部数据源、查不到就不能动"的点**：形状猜错会让
溅射范围整个偏掉，而且**不会报错**——只是伤害数字安静地不对。按纪律记在这里，
先做别的，不停在原地。

**要查的是什么**：撼地者（子职业 `hammer`）特性的溅射覆盖——
是目标格的四邻十字、还是含目标格的 3×3、还是别的形状。
查证时可一并核对：`prts.wiki` 的特性页 / 游戏本体 `character_table` 里
该子职业的 `trait` 字段 **与** `ranges` 表是否给出了溅射掩码。

### 十二之一、2026-09-18 第二轮：**形状键找到了**，问题缩小为"语义待定"

上一版把这条写成"取不到"，**这一步已经推进**：

```
sqlite> SELECT range_id, blackboard FROM operator_trait
         WHERE char_id='char_1051_headb2';
range_id = None
blackboard = {"attack@ability_range_radius": 1.0, "attack@atk_scale_2": 0.5}
```

* **形状由 `attack@ability_range_radius` 给出，值是 1.0**；
* 那个 `0.5` 就是特性溅射的**底数**（`attack@atk_scale_2`），天赋1 的
  `damage_scale: 1.24` 乘在它上面 → **62%**。
* 之前在 `operator_attr` 与 `operator.raw_json` 里翻不到，是因为**找错了表**：
  结构化特性住在 **`operator_trait`**（正文 `override_description`、
  系数 `blackboard`）。全库用这个键的只有 `hammer` 一族 4 位，全是 1.0。

**仍待裁定的是"半径 1"的几何**：是曼哈顿半径 1（目标格 + 上下左右四邻 = 十字 5 格），
还是切比雪夫半径 1（含目标格的 3×3 = 9 格）。**现有资料不足以裁定**：

* 仓库里**已有同一口径的先例**，但那是敌人侧自己命名的字段——
  `EnemyUnit.skill_atk_cross` 的注释写着「溅射十字半径（1 = 目标格 + 上下左右四邻）」
  （`unit.py:767`）。沿用它**是自洽的，但不是游戏数据的证明**；
* 上网只得回一页 2022 年的 PRTS 沙盒残页（菲亚梅塔一条），没有撼地者；
* 特性正文只写「目标周围的其他敌人」，**没有**给出格数——而**同一份数据里
  天赋1 的第二段明写「周围四格」**，说明这套文案在需要时会写死格数；
  特性没写，恰恰说明它不可从正文推。

**结论：暂不实现，也不猜。** 实现时把形状收在一个常量里，并在守卫里钉住，
使"十字 → 3×3"是一处改动。要裁定时最可靠的路径是**实机录屏逐格验证**，
其次是游戏本体的 `ranges`/`tile` 相关表。**顺带记一条判据上的教训**（本轮踩到）：`damage_scale` 这个键**归得了类**
（进 `buff` 桶），因此它会**通过审计的第一道筛子**，而第二道筛子只在第一道
失败的键上跑——于是"这个键战斗层根本没读"这件事，两道键级筛子**都看不见**。
补的第三道筛子是**天赋级**的（天赋名在不在源码里），才把它那一族照出来。

## 十四、**天赋给的属性加成整体没被应用**——但"补上"这件事不能一刀切

2026-09-18 查凯尔希·思衡托时撞见的，**影响面是全库而不是某一位**：

```
天赋要     遗尘守望 {max_hp: 0.25, def: 0.25, block_cnt: 1.0}
```

`blockCnt` 与库里原始值**一模一样**——天赋那三项**一项都没进去**。

**全库天赋黑板里的出现次数**：

| 键 | 次数 |
|---|---|
| `atk` | 416 |
| `def` | 183 |
| `attack_speed` | 170 |
| `max_hp` | 95 |
| `block_cnt` | 41 |
| `respawn_time` | 26 |

其中**只有 `attack_speed` 有通用链路**（`ak_tactic/operator/attack_speed.py`

**⚠ 但千万不要照着这张表批量补——会同时引入两类错，而且都不报错：**

1. **重复计算**：星熊「特种作战策略」的 `def: 0.06` 是**发给全体重装的光环**，
   不是自身加成（她自己恰好是重装才吃到）。按"天赋 `def` 键 → 加到自己身上"
   批量补，她会被加**两遍**。
2. **把有条件的当成常驻**：焰狐龙梓兰「翔虫机动」的 `atk: 0.1` 要求
   「部署至**上次部署位置周围**」才生效——常驻补上去，她**整场**白拿 10% 攻击。

所以这张表的正确读法是：**它是一个待分类清单，不是一个待批处理清单**。
每条天赋的属性键都要先归到三类之一——**自身常驻**（如凯尔希「遗尘守望」）、
**发给别人的光环**（如星熊，已在 `TeamAura` 里）、**有条件的**（如翔虫机动，
该由触发条件驱动）——才谈得上接线。

**这一条同时解释了第三道筛子里那批"统计类天赋"报出来的欠账**：它们**不全**是
真欠账（星熊那条已经建了），但也**不全**是误报（凯尔希那条是真的没建）。
**逐条分类之前，任何一种批量改法都是错的。**

## 十六、两条「已查清、缺管道」的欠账（2026-09-18 定点核查）

这两条此前记的是「卡在数据」，本轮查实**数据是有的，缺的是接线管道**：

### 1. 泥岩「手足相惜」——受到来自【萨卡兹】敌人的伤害降低 30%

* **数据有**：`category = 萨卡兹` 是敌人库里真实存在的取值（`enemy` 表，
  按 `name`/`ability`/`raw_wikitext` 命中 177 条）。
* **缺的是**：运行时 `EnemyUnit` **没有** `category` 字段（`battle/unit.py` 里
  搜不到），所以要先把它从敌人库透传进战斗单位。
* **还缺**：干员侧**没有**「按攻击者来源改受到的伤害」的通道——`sim.py` 里
  连 `damage_resistance` 都搜不到（那个键目前只活在数据里）。
* **落点**：`battle/sim.py` 里敌人攻击干员的结算处（`dealt = target.take(`
  那一块，约 3133 行），攻击者 `e` **就在作用域里**，所以判据写在那里最省。

### 2. 阿斯卡纶技3「降临」——使范围内的敌人物理与法术命中率 −50%

* **语义**：这是加在**敌人**身上的命中率减益，对**任何**被它攻击的人都生效，
  不是只对阿斯卡纶自己。按期望读等价于「被它打的人多 50% 闪避」，可线性化。
* **缺的是**：`EnemyUnit` 没有命中率字段，`OperatorUnit.hitrate_malus_*` 也没有。
* **落点同上**：`sim.py` 的 `dodge_phys=target.dodge_phys + target.talent_dodge_phys`
  那一行（约 3136 行）——**攻击者 `e` 同样在作用域里**，所以把减益放在攻击者
  身上、在这一行叠加是最短的接法。
* **同源未做的那半**：「敌人未命中自身或自身闪避时回复 8% 生命」
  （`attack@hp_ratio`）——它与上面这条同源，等上面接好再一起做。

**结论**：两条都不是"查不到"，是"要动敌人的字段与一条新通道"。
**已把落点精确到行**，下一轮可以直接动手，不必重新排查。

**⚠ 2026-09-18 补充（本轮实测后改写上面这段的结论）**：上面写的"缺的是接管道"
**说得太轻了**。实际动了一次手，守卫当场把真相照了出来：

* `battle/sim.py` 造敌人时，`stats` 来自**游戏本体**那一路
  （`ak_tactic.gamedata.EnemyLibrary`），**它根本不带 `category`**——
  补了 `getattr(stats, "category", "")` 之后，一局打下来 **14 只敌人全是空串**。
* `category` 只存在于**独立的敌人库** `data/enemydb.sqlite`（那张 PRTS 来源的表）。
  两库**不共用文件、不互相引用**（这是设计上明确的）。
* 所以"补个字段"是不够的：要把 `category` 接进战斗层，得**先把敌人库引入
  `battle/` 的取数路径**——那是一次结构性的改动，不是一行。

**结论修正**：泥岩「手足相惜」与阿斯卡纶技3的命中率**不是"就快好了"**，
而是**依赖一件尚未存在的事**（战斗层能读到敌人的 PRTS 侧属性）。
已实现的部分**全部回退**——因为一个"永远不触发"的机制比没有更糟：
它会让审计的第三道筛子**误报为已建模**。

**教训（本节最值得留下的）**：给机制补数据源时，**必须用一局真实对局验它真的
触发了**，不能只验"函数算得对"。本轮纯逻辑断言 6 条全绿，端到端那一条才是
唯一有信息量的——**它一红，前面 6 条绿就全不算数**。

## 十七、可露希尔：一条**干净可做**、一条卡结构（2026-09-18 分诊）

她是本批除焰狐龙梓兰外欠账最多的一位（无人读 12、无检测器 2）。逐条摊开后：

### ✅ 可直接做：天赋2「极限调度」的攻击力那半

正文：「携带可露希尔时，**部署费用下限降低 3**，**【罗德岛】干员攻击力 +4%**」
——`{atk: 0.04, cost: -3.0}`。

* `atk: 0.04` 这一半是**干净的**：它就是一条阵营光环，与已建的
  「万众巨潮」同型，**可以复用 `TeamAura`**。
* **但要注意差别**：万众巨潮的 `faction` 是**翻倍**语义（该阵营 ×2、其他人 ×1），
  而这条是**筛选**语义（**只有**该阵营拿到 +4%、其他人 0）。
  现有的 `TeamAura.faction` 表达不了后者，要新加一个
  **`faction_only`**（照 `profession` / `self_only` 那两处的写法加一个筛即可）。
* 需要的数据：`operator.team_id` 里【罗德岛】的取值（干员库里本来就有，
  与「万众巨潮」用的 `STUDENT_TEAM` 同源）。
* `cost: -3` 那一半**不在战斗层**——「部署费用下限」是**名册/费用规则**侧的量，
  该落在 `search`/`verify` 的费用口径里，不属 `battle/`。

### ⚠ 卡结构：天赋1「精准投放」与三个技能

* **「精准投放」**：「可以在战术点召唤**指挥中心**协助作战，其被击败后 15 秒
  自动刷新；战术点效果范围随携带技能变化，**效果范围内的友方单位视为自身的
  援军**」——这是一整套**战术家子职业的召唤/归属**系统（战术点、指挥中心、
  「视为援军」的身份传播）。仓库里没有这套，**不是一条天赋的体量**。
* **三个技能**的黑板大量围绕**费用**：`cost` / `cost_period` / `cost_return` /
  `cost_add_max` / `cost_per_add` / `closur_s_2[add_cost_period].cost`。
  其中 `[add_cost_period]` 是**方括号条件键**（与已接的 `[second]` 同族），
  但**「add_cost_period」这个条件由什么激活**尚未查清——按纪律，
  **查不清就不接**，接错会让那族键静默用错值。
* **技3「Q.E.D.」的减速**：`attack@slow_down`（0.06）/`slow_down_max`（0.6）/
  `slow_down_time`（3 秒）/`max_stack_cnt`（10）——是**可叠加的移速降低**。
  既有裁定是「停顿」与「移动速度降低 X%」**是两个量、不可合并**，
  所以这条要按「移动速度」那一路接，且要判它是否与既有的移速通道同型。

**结论**：「极限调度」的攻击力半条是**现在就能做的**（加 `faction_only` 即可）；
其余要先把**战术家结构**或**费用规则**落下来，或先查清 `add_cost_period` 的激活条件。

### ⚠ 2026-09-18 补充：上面写的「复用 TeamAura + 加 faction_only 即可」**少说了一步**

本轮去查【罗德岛】该从哪个字段取，**先踩了一个坑**：

* `team_id` 那列**不是**答案。它的取值是 `rainbow`(8) / `student`(7) /
  `reserve6`(7) / `action4`(6) …，而且 **能天使、阿米娅、可露希尔的
  `team_id` 全是 `None`**——**`None` 既不等于罗德岛，也不等于没有归属**。
  照 `team_id` 判会把企鹅物流的能天使也当成罗德岛。
* 真正的字段是 **`nation_id`**：阿米娅 `rhodes`、可露希尔 `rhodes`、
  **能天使 `lungmen`**、星熊 `lungmen`。所以【罗德岛】= **`nation_id == 'rhodes'`**。
* （`group_id` 是第三个数：星熊 `lgd`、能天使 `penguin`，那是**组织**，
  与 `nation_id` 的**国家/势力**、`team_id` 的**小队**各是三件事。）

**所以做「极限调度」还要多接一条**：`OperatorUnit` 目前只有 `profession`
（为「特种作战策略」加的），**没有 `nation_id`**。要照 `profession` 那条路
再走一遍三处——`unit.py` 加字段、`verify.py` 的 `kw`、`tools/check_battle.py`
的 `make_unit`——然后才轮到 `TeamAura.faction_only`。

**教训与第十六节那条同源**：`team_id` 这个名字"看起来就是阵营"，
而它其实是**小队**；一次全表核验（三人取值一摆）就能当场分辨。
**凡新字段先全表核验再下判据**——这条已经是本项目第三次咬人了。

## 十八、新约能天使：**没有干净件**，两条天赋各自卡在别的东西上（2026-09-18 分诊）

### 「火力电台」——卡在**弹药系统**

正文：「在场时，每当**有友方干员的弹药被消耗**就会回复自身 6% 生命值，并有
20% 概率立即对该干员攻击范围的敌人召唤一次轰炸，造成相当于自身攻击力 105%
的物理溅射伤害」——`{aoe_atk_scale: 1.05, damage_scale: 1.05, hp_ratio: 0.06,
prob: 0.2}`（精 2 为 1.5 / 0.25）。

* 触发条件是**全场的弹药消耗事件**，不是她自己的动作。要接它，得先有一处
  **统一的"弹药被消耗"钩子**，且能被所有携带弹药类技能的干员触发。
* 另外那 20%/25% 是一个**离散概率**（是否召唤轰炸）。按既有裁定，

  "多打一次溅射"这件事本身，但**伤害是可线性化的**——
  这一点**需要一条裁定**才能定，与「随机友方」同源。

### 「铳弹协约」——卡在**名册级分类**

正文：「在场时，**携带弹药类技能的干员**攻击力 +9%，对**【拉特兰】干员**的
效果翻倍」——`{atk: 0.09, mult: 2.0}`。

* **形状本身是现成的**：这正是已有 `TeamAura.faction` 的语义
  （该势力翻倍、别人 ×1）——与「万众巨潮」的【乌萨斯学生自治团】同型。
* **但底子不是"全场"**：只有**携带弹药类技能的干员**吃到 +9%，
  其他人是 0。所以要先有一份**"谁携带弹药类技能"的名册级分类**。

### 判据：wiki 一句话里并列了**两种判定**

prts.wiki「怒潮凛冬」页的**备注**栏（此前只查了特性正文与 `ranges` 表，
没查备注）原文：

> ※高台溅射效果为独立于攻击的效果，其以该次攻击中心为中心，选择 **1.0 半径内
> 的地块**触发溅射（**重叠判定**），伤害溅射范围为**周围 4 格 + 本格**
> （**格子判定**）

这句话把两种几何**分别点名**：

* **重叠判定** —— 备注把它点名在**高台触发**那一半上。**特性溅射（打到敌人）
  那一半，wiki 并没有单独写判定方式**；它用的半径来自黑板
  `attack@ability_range_radius`。本实现**按同一读法处理**（半径 1.0 的"周围"
  = 圆盖到的地块），理由有两条：① 若按格心距离算，半径 1.0 只剩十字五格，
  与「目标**周围**的其他敌人」这种包围语感不符；② 同一支特性上两处半径没有
  理由用两套几何。**这是一处有据的推断，不是 wiki 的原话**——按纪律标在这里。
* **格子判定** —— 天赋那一半里的「周围四格 + 本格」对应范围码
  `x-5`，实测 `attack_range` 表里就是 `[[-1,0],[0,-1],[0,0],[0,1],[1,0]]`，
  即十字五格。**天赋的高台溅射走这一种。**

两种判定在同一支特性上各管一段，**照抄任一种到另一段都会错**，
而且在"目标站在格心"时只差四个斜邻——错得不显眼。

**闭圆还是开圆（这一条是被数据反推出来的）**：技3「无可抵挡」把溅射半径
写成 1.5（`HAMMER_SPLASH_RADIUS`）。半径 1.5 时，**正交两格**的地块离圆心
最近的点距离**正好是 1.5**；若判据取严格小于，1.5 与 1.0 会盖出同一片 3×3，
技能正文那句「**溅射范围更大**」就成了空话。所以判据取**闭圆**
（`<= 半径 + eps`）：1.0 → 3×3 九格，1.5 → 3×3 加四条正交臂共 13 格。
两条半径必须**分辨得出差别**，这是"更大"两个字给出的硬约束。

### 二十一、平A 把技能倍率算了**两次**（已实测，**待裁定改哪一侧**）

| 模型实得 | **1,251.0** | 3,753.0 |

比值 **1.4500**——正好是倍率本身，即同一条倍率被乘了两次。

**成因：两侧各自都对，合起来错**

* `SkillEffects.attack_power()`（`OperatorUnit.current_atk()` 走它）返回
  `atk × (1 + 攻击力增益) × atk_scale`，而 `check_battle [3]` 还钉着
  「机械师总倍率 **9.88** =（1+2.8）×2.6」这个社区标定值 ⇒ **这一侧自洽且有据**。
* `resolve_damage` 的契约是 `atk` = **最终攻击力**、`scale` = **技能给的伤害倍率**
  （「造成相当于攻击力 480%」→ 4.8）⇒ 普攻循环里
  `resolve_damage(op.current_atk(), scale=eff.atk_scale)` 自然就是两次。
* 旁证：普攻循环里 `hit_scale` 会被 `final_hit_scale`（即 `atk_scale_2`）**整个替换**，
  说明 `atk_scale` 一族在那一层是**面板相对**的倍率，与 `resolve_damage` 的契约一致。

**影响面**（`level = 10` 全库扫）：`atk_scale` 267 条 + `attack@atk_scale` 75 条，
**受影响干员 238 位**。三条回归基线**全在里面**：阿米娅 `attack@atk_scale 0.6`（8 连击）、
德克萨斯 `atk_scale 1.7`、圣聆初雪 5.2 / 3.8 / 2.6、望 1.35 / 5.8 / 3.8。
⇒ **改这一侧会移动 1-7 与 SR-EX-8 的基线**，必须重新标定，所以不是随手能改的一行。

**两条候选改法**（都能让平A 回到正文口径，差别在 `current_atk()` 的含义）：

1. **改 `current_atk()`**：让它只表示**面板攻击力**（含攻击力增益与击杀叠层，
   **不含**技能倍率），倍率统一由 `resolve_damage(scale=…)` 乘。代价：`[3]` 的
   9.88 那条要改写成「一次出手 = `attack_power` × `atk_scale`」；`_trait_splash`、
   积雪踏入伤害、`dot_per_sec`、全场总攻击这些 `current_atk()` 的消费者会一起
   变成面板口径（多半更对，但要逐个核）。
2. **改平A 循环**：`power` 用面板值，或把 `hit_scale` 在非末击时取 1.0。
   改动面小，但「技能倍率住哪」这件事继续留在两个地方，下一次还会撞。

**裁定前状态（留档）**：本批的能天使 / 新约能天使 / 可露希尔 / 阿斯卡纶都带这条键，
当时的伤害一律偏高；`[38]` 节因此只钉「连发笔数、出手间隔、抵挡、阻挡」
这些**不受本条影响**的可观测量。
（怒潮凛冬技3 不受影响：它是技能自打的通道，那个模块自己按
`atk × (1 + atk_base + 0.3i)` 再乘 `atk_scale`，只乘一次。）

**裁定与后果（2026-09-18，博士裁定：改 `current_atk()` 一侧，已落地）**

改的是**含义**，不是删掉某一处：

* `SkillEffects.attack_power()` 去掉 `× atk_scale`，退回面板口径；
* `OperatorUnit.current_atk()` 的两支合并成一支（`面板 × (1 + 攻击力增益 + 击杀叠层
  + 全场光环)`），技能倍率一律由 `resolve_damage(scale=…)` 乘；
* CLI 技能页的「一次攻击」显式写成 `attack_power(atk) × atk_scale`（展示值要合起来
  才是玩家看到的那一下）；
* 守卫 `[3]` 拆成两段：面板口径 3.8，一次出手总倍率 9.88 = 3.8 × 2.6（同一条
  社区标定值，只是挪到正确的一层去钉）。

**同一批里另发现一条独立缺口（已修）**：凯尔希·思衡托技2「保护性拒止」正文是
「击中时对目标周围所有敌人造成相当于攻击力 380% 的**真实伤害**」，而解析出来的
`true_damage=False`——她这一下此前还要吃防御与法抗。判据 `_wants_true_damage`
**刻意只认「伤害类型变为真实」**（用「真实伤害」当判据历史上会误判 28 条附加伤害、
同时漏掉 8 条真正的类型改写），她这句属于"整条攻击的伤害"、只是措辞带了「击中时」
——是刻意收窄带来的**漏网**。修法是补一条**三条件同时成立**的判据
（「攻击变为」+「相当于攻击力」+「真实伤害」）：只有"这一击被换掉了"才说明
后面写的是它的伤害。全表（level=10 去重）核对：新增命中**只有她这一条**，
另三条（微尘碰撞 / 敌人每秒受到 X 点 / 耀阳部署时）都不含「攻击变为」，保持不认；
`check_battle` 里配了正反两条守卫与一条**全表命中面**断言，实战上则钉
「打防御 5000 / 法抗 100 的靶子仍是满额」。
