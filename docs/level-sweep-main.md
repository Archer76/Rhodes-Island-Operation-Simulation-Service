## 二、口径（读表之前先读这一节）

### 1. 关卡集口径

* 本台账的关卡集 = `tools/check_go_all.py:cached_levels()` ∩ `^main_(0[0-9]|10)-` 
  = **第 0～10 章在盘上缓存里可达的全部关卡 id，共 262 个**。
  其中普通档 `main_XX-YY` **141 个**，四星档（突袭）变体 `main_XX-YY#f#` **121 个**。
* ★ **两套口径不许并列**：`docs/mainline-stages.md` 里的 `C_main` 是 `main_` 行**按 code 去重**
  之后的关卡数（267），与这里的「262 个关卡 id」**不是同一个数**（同一关的普通档与四星档是两个 id、
  共用同一份 `data_path`）。本台账按**关卡 id** 报，因为三层读数是一次一次构建跑的。
* 本次**未覆盖**第 11～17 章（缓存里另有 172 个 `main_` id）。跑到哪写到哪，不做抽样。

### 2. 有夹具与没夹具：合成计划这一刀

* 有作业夹具（`fixtures/plan-main-*.json`，经 `level_mech_inventory.plan_fixture` 判定）
  的**只有 3 关**：`main_00-01、main_01-07、main_02-01`。这三关用**真夹具**跑。
* 其余 **259 关没有作业夹具**。按博士裁定，一律加 `--synthetic-plan`：用一份**明确标成合成**的
  单干员计划（克洛丝，精英一 55 级，位置 [1,1]，技能 0）硬跑。
* ⚠⚠ **合成计划关的 B 层判决四数只说明「这一关跑得动」，不说明「这一关有人能过」。**
  同理，合成计划关的 C 层只说明「这些机制在这条路线上被走到过」，不是这一关的机制全覆盖。
* 不加 `--synthetic-plan` 时入口会**大声拒跑**（`⊘ 不适用`，rc=3）——本台账里 `⊘` 计 0 关，
  是因为这 259 关全部按博士裁定改用合成计划硬跑了；**这个 0 不代表入口的拒跑分支没被验过**
  （单独跑 `python tools/level_full_sim.py main_00-02` 得到 rc=3 与 `⊘ 不适用于本入口`）。

### 3. 三层各自的判红形状

| 层 | 读什么 | 判红 |
| --- | --- | --- |
| A 算得出 | `buildspec` 的 19 个顶层键是否造齐；`missing_keys`／`gated_keys`；闸门 `reasons` | 缺键、或被闸门/难度修饰层**拒跑** |
| B 跑得动 | `sim` 的判决四数（won／life／kills／leaks）＋ elapsed | 跑不起来、或判决缺字段 |
| C 机制真被行使 | 机制清单（数据侧现算）与运行期痕迹**并排** | 清单里有、痕迹里一条都没有 |

★ C 层为什么是「并排」而不是「数痕迹」：只数痕迹会漏掉「清单里有、痕迹里没有」那一类
（那正是「算了但没生效」的样子）；只看清单也不行（清单是数据里**声明**的键，不是运行期**走到**的机制）。
本台账的 C 栏只报**读数**（痕迹标签种数／笔数、清单键数），**恒等与否由人判**——
工具不替人下这个结论，本台账也不。

### 4. 一条读表时不能忘的限定

「0 条痕迹」先要证明**那次跑成功了**。本台账把 C 层零痕迹与「B 层失败」严格分开计数：
只有 `B ok=True`（判决四数都在）的关才进入 C 层零痕迹的判定范围。
