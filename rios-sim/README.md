# rios-sim

R.I.O.S. 的 Go 战斗引擎、规格构造与搜索实现；Go TUI 位于 `cmd/rios-tui/`。Python 工程侧保留登录、名册桥接、建库与数据抓取等工作。

## 当前边界

Go 不是只能消费 Python 算好的数字：引擎可读取关卡与 gamedata、解析练度和技能元数据、构造规格、生成几何候选并执行 beam 搜索。既有 Python 模拟器及冻结读数用于比较和变化探测，不是 Go 实现的正确性标准；差异应按机制来源核实，不能仅为对齐旧结果改战斗真值。

- `sim` 可接收预构造规格，或关卡、计划与名册的查询形式；后者在 Go 内构造规格。
- `solve` 搜索落位、朝向与部署顺序。按博士 2026-10-06 裁定，**每名干员只部署一次**，不搜索主动撤退、再次部署或延后落地时刻。“一次性放完”不是同帧落地，自动请求仍按计划顺序等待真实费用。
- 模拟器可执行外部计划的撤退／死亡后再部署。实际在场、再部署冷却、部署位及费用由战斗循环判断，搜索范围限制不删除该能力。
- MAA 导出只接受可保真的纯顺序自动部署；显式时刻、手动技能及撤退时序具名拒绝。模组要求按部署与名册的有效值解析，未知 ID／类型具名拒绝。导出形状正确不等于实机验证。

## 数据路径与固定输入

引擎的 `RIOS_DATA` 是 **gamedata 目录**，未设时使用相对 cwd 的 `data/gamedata`；`RIOS_DB` 用于 sqlite 数据根，两者不能混用。Go TUI 可从绝对数据库位置推导 gamedata 位置并传给子进程。发布树的数据根是 `eng/data/`；游戏数据和 Python 运行时不随测试包分发。

固定关卡、名册、敌人库与按完整练度／技能等级索引的元数据按请求或一次解算复用，发布给候选的输入只读，构造与运行输出独立。技能表全局惰性加载由互斥保护，完整成功后才发布；对外表快照连原始 JSON 字节一起复制。全局技能表读取失败可重试，但同一请求缓存键的 `sync.Once` 错误缓存语义不变。

## 机制与结果可信边界

目标是完整建模，**不以期望值近似替代未完成机制**。当前技能与已解锁天赋按来源产生 `mechanism_placeholders`，区分未识别载荷与已识别但消费者未实现。占位保留来源、部署实例、键值、原始黑板与原因；实际方案存在占位时不返回战斗胜败／星数。预构造规格同样检查占位及已知近似字段，不能绕过拒判。

搜索仅有未完成候选时返回 `status=incomplete`、`stars=-1`；完整候选可保留其判决，其它候选占位仅作排除账。**空占位不是全部机制已建模的证明**，模拟胜利也不是未经实机验证的稳通承诺。

场地与活动机制位于 `mech/`，通过注册表按规格点名取用；不是空层。`ping.mechanisms` 返回当前二进制登记的名称，但名称存在、载荷可解析、某个测试通过，都不等于全部条件与战斗消费者完整。机制读取只读视图，修改通过效果请求交给主循环；缺失机制具名拒绝，不允许删除占位或关闭守卫来“全绿”。

自动部署由运行期费用控制；技能回费、撤退退款、击杀奖励共用实际余额。费用不足的自动请求等待，显式时刻只尝试一次；在场、冷却或满位不改为自动等待。P1 三星早停采用首个消费者观察到的合格三星胜出，不是整层最优；取消会排空并等待 worker／调度退出，模拟在帧边界协作取消，不返回部分判决。

## JSON 行协议与 Python 客户端

标准输入每行一个请求，标准输出每行一个最终 JSON 应答；`id` 回声、`ok` 与具名 `error` 区分成功与拒绝。`ping` 核对协议版本；查询命令还包括 `load`、`opstats`、`buildspec`、`candidates`、`solve` 等，具体输入以当前请求类型和命令处理为准。`solve_progress` 进度写 stderr，不能当最终 stdout 回包。

```json
{"id":1,"cmd":"ping"}
```

Python 的 `ak_tactic.simgo.client.Simgo` 必须传明确 exe，或设置 `RIOS_SIM_BIN`；未钉定／文件不存在均具名拒绝，**不静默回退到旧工作树二进制或 Python 模拟器**。单次 timeout 覆盖获得连接锁后的写入、flush 与完整响应行等待，不含序列化与锁排队。超时、EOF 或非法协议会关闭连接并回收进程、线程与管道；不自动重启，迟到响应不能供下一请求使用。业务 `ok=false` 的完整响应不自动关闭连接。stderr 独立容错排空并限量保留日志尾部。

## 构建与离线回归

从本目录构建，产物路径应明确，不覆盖已钉定的旧验收仪器：

```powershell
$env:GOPROXY = 'off'
$env:GOTOOLCHAIN = 'local'
go test -v ./...
go vet ./...
go build -o ../out/acceptance/rios-sim-local.exe .
go build -o ../out/acceptance/rios-tui-local.exe ./cmd/rios-tui
```

从仓根运行客户端与发布门单元测试：

```powershell
python tools/test_simgo_client.py
python tools/test_selftest_gate.py
python tools/test_release_identity.py
```

数据测试应确认真实 PASS，SKIP 是未行使，不能算通过。当前机器 CGO=0 且 PATH 无 gcc/clang，race 尚未行使，不写成 race 通过，也不自行联网安装。

## 发布与测试包

`tools/build_release.py` 生成独立目录：`rios-tui.exe`、`rios-sim.exe` 与 `eng/`；双击 TUI 是入口，无额外启动壳。发布验证隔离继承的组件与数据覆盖，并对包内引擎与桥进行离线握手、记录协议与 SHA256。缺件负对照不能被外部组件补位。桥握手身份记录不包含账号或凭据状态。

`rios-tui -selftest` 的静态 required 清单全部必须实际行使，包括真实名册、在线扫码和源码扫描。失败、缺前置或 skip 都不能满足发布门；结构化报告而非勾数／rc 单独决定验收。`--no-selftest` 可以构建测试包，**只能标为 unverified**；离线组件 smoke 不替代完整自检、MAA 实机或全部机制验证。缺环境不能声称全绿。

详情与裁定见仓根 README。旧性能／对拍数据属于各自版本和输入的历史证据，不作为当前构建的性能或机制完整性承诺。
