# rios-sim

R.I.O.S. 的**第二份**战斗模拟器，Go 写的。原版是 `ak_tactic/battle/`（Python）。

## 为什么要另写一份

HS-EX-4 一次解算 **214 秒**——几千场完整战斗在纯 Python 里跑。原版已经做过就地展开
的优化（1.09–1.18×，见 `docs/tui-plan.md` 第十二节），**再榨只有 20%，要的是一个量级**。
微基准：2×10⁷ 次浮点循环，Python 2.49 秒 / Go 0.017 秒。

## 与原版的关系

博士 2026-09-18 的裁定：「保留原版项目结构不动另写一份新的模拟器」。

* `ak_tactic/battle/*` **一行不改**——它继续是三关基线（1-7 / SR-6 / SR-EX-8）与
  `tools/check_battle.py` 那 793 项自检的**权威实现**；
* 这一份是独立的：自带 `go.mod`、自己的构建、自己的二进制；
* **判决必须与它逐位对齐**才有资格接班。对拍台是这套东西的第一件产物，不是最后一件。

## 边界：Go 侧只跑战斗，不做取数

输入是**已经完全算好的数字**（干员最终属性、技能数值、敌人属性、波次时间轴、地图
可部署格），输出是判决与时间线。Go 侧**不读数据库、不联网、不做练度折算**——那条链
在 Python 里已经验证过，搬过来只会多一处会漂的实现。

## 协议：stdin/stdout 上的 JSON 行

一次进程、批量作业。选它而不是 Python 扩展模块，是为了免掉 FFI 构建链，并直接复用
`ak_tactic/parallel.py` 那套多进程并行。

```jsonc
// 请求（一行一个）
{"id": 1, "cmd": "ping"}
{"id": 2, "cmd": "sim", "spec": { /* 见下 */ }}

// 应答（一行一个，与请求同序）
{"id": 1, "ok": true, "pong": {"version": 1, "go": "go1.26.0", "spec_done": false}}
{"id": 2, "ok": true, "verdict": { /* … */ }}
```

* `ping` 用来在开跑之前核对**协议版本**。二进制与调用方版本不一致的症状是"判决微妙地
  对不上"，那是最难查的一类错，所以在门口挡住。
* 未实现或出错一律 `ok:false` + `error`，**绝不返回假判决**——调用方拿假判决当"跑完了"，
  对拍台就再也测不出东西。

## 构建与自测

```bash
cd rios-sim
go build -o rios-sim.exe .      # 本机 Go 1.26，无需联网（GOTOOLCHAIN=local）
echo '{"id":1,"cmd":"ping"}' | ./rios-sim.exe
```

Python 侧的门：`python tools/check_simgo.py`（本机没装 Go 时**跳过**而不是失败——
克隆仓库的人不该被一个新组件拦在门外）。
